# 同源镜头数据与排版

所有品类新项目用`build_jimeng_boards.py`。临时工作区每C-ID一份JSON（不交付），表图和宫格图一次导出；CSV和TXT也从此已确认镜头记录整理，不各自重新编镜号。兼容旧`assemble_storyboard.py`的基础时间/帧字段，但新工具新增必填的分段标识、详细执行信息和逐帧短说明。

## 字段

- 顶层：`title`、非空`revision`、`generation_id`（如C02）、`global_offset_s`（该段在全片起点）、`aspect_ratio`（视频及格内画幅）、`total_duration_s`（本段时长）、有序`shots`。
- 镜头：稳定`id`（如S05，第二段不改为S01）、本段`start_s`、`duration_s`、`details`、`frames`。同段从0连续，无重叠/空洞；完整项目另检查跨段全局衔接与S-ID不重复。任务生成时长/裁切保留范围记录于README。
- `details`：以下15个字段全部为非空字符串，确实不适用时明确写“无”及必要原因，不能用占位词填满。脚本只检查字段存在，不理解语义。

15字段是当前排版接口，不代表每镜必须有15类独立事件。camera只写机位，action只写主体操作，states写起终结果，parallax只写本镜需要的空间变化；不适用时可写“无；固定机位阅读细节”等简短事实，不为填满字段编造运动。公共设置由策划一次确定，当前接口仍逐镜填所需值；不新增未实现的继承字段。TXT整理成自然执行句，不拼接字段。

|字段|上传表图需要读到的内容|
|---|---|
|scene|场景ID、干净背景/台面、室内外、角度、主体位置与比例|
|shot_size|全景/中景/近景/特写等景别，与画面一致|
|dialogue|准确台词/旁白及出声主体，无则明确无旁白/台词；不混入字幕|
|purpose|此镜要读清的主要信息/卖点；细节镜明确局部与主体的定位关系，不能仅写“体积证据”|
|camera|起终机位、主运动路径、方向、速度、停稳读图时间|
|lighting|主光方向、色调与固定光源关系；运动实际影响的投影/反射及跨场合理变化|
|states|同一主体/部件/道具的起态→过程→终态，补入顺序与目标造型、遮挡再现；每步结果衔接下一步，与格说明对应|
|action|商品/部件/手/道具的接触、支撑、持续过程与自然间歇、落位/持物结果；只写真实机构和动作次数|
|environment|驱动导致的物件/屏幕/柔性部位/连接物响应，以及触发暂停后的状态；光影按实际条件联动，不适用则明确稳定|
|parallax|空间镜写可辨的视点/遮挡变化；操作镜按需写接触空间；静态阅读镜可写“无；固定观察”，不强制三维证据|
|copy|准确成片文案/尺寸数字、单位、出现时间和位置；无则明确无字幕|
|sound|音乐、触碰声、旁白设置及接续|
|transition|入镜/出镜、匹配点、运动方向、与下镜/下段的接缝|
|reference|仅本镜需要的本段附件/图片序号及身份、状态、完成态或环境角色；状态限定到S-ID/state，不把所有附件重复绑定每镜；研究留内部记录|
|constraints|本SKU固定与可动部分、关键部件/道具身份、已核数量/连接与允许变化；不写未上传原片的禁用清单|

`frames`至少一项，每项`state`（start/key/end，按此序且不重复）、`file`（相对于JSON的实际图片路径）、`summary`（格下简短中文说明）。同镜复杂动作按需2–3状态；不靠重复裁切假装真实机位变化。`summary`是当前格画面的解释，不是整镜提示词或广告字幕，例如“S05/key：第三次插入中，手仍握住枝条，器内保留前两次花材”。编号由工具排，不必在summary再次手写。

终态倒推与多步状态按[状态衔接规则](terminal-state-and-motion.md#2-参考图制作与状态衔接)表达：当前每镜只支持start/key/end三种状态，不添加key2或step1；多镜承载真实切点，连续动作在表/TXT写全并选关键三格，不能把缺步骤伪装成完成。内部目标完成态来源、反向移除清单和审阅情况放planning_notes/说明书，上传字段仅写正向动作与实际附件。

图片内容按[商品与镜头保真](reference-and-shot-fidelity.md)逐张核对；共用计划/相同镜号不能证明构图、轨迹和动作状态一致。TXT按镜头记录重新组织简洁执行句，不机械拼接details字段。

蒙太奇的播放顺序、叙事线返回和切点按[镜间组织](montage-for-product-video.md#落到现有交付不加字段或文件)映射到scene/states/transition等现有字段。返回同场景是新的镜头出现，使用不同S-ID；start/key/end仍只属于同一镜头。多宫格输入按[即梦适配](jimeng-model-adaptation.md#多宫格怎么迁移)说明已用槽和状态组，不另增字段。

三维变化与连续交互按[三维场景演绎](volumetric-scene-direction.md)落实到现有字段，不扩展脚本结构。格下文字只描述该帧可见状态，持续过程写入表/TXT；不得用同图裁切缩放伪造start/key/end。

内部可另设顶层或每shot的`planning_notes`（临时计划字段，不是交付文件）记证据/模板来源/疑问，排版器只渲染上述白名单字段和frames.summary，不画planning_notes。字段存在不代表内容已净化；人工检查details/summary不得混入内部信息。CSV中仍可保留事实与研究来源，但与上传用reference分列。

  "global_offset_s": 15,
  "aspect_ratio": "16:9",
  "total_duration_s": 4,
  "shots": [{
    "id": "S05", "start_s": 0, "duration_s": 4,
    "details": {
      "scene": "L02，干净窗边台面，斜前方，成品居中完整入画",
      "shot_size": "中景",
      "dialogue": "无旁白、无台词",
      "purpose": "展示摆放完成后的空间效果",
      "camera": "相机从正前方沿台面前的开放区域缓慢移到右前方，持续朝向主体，最后停稳",
      "lighting": "左侧柔和窗光，商品颜色与身份图一致",
      "states": "起：正前方看台面中心的成品；中：右侧面逐渐显露、边缘重叠改变；终：右前方完整成品停稳收尾",

## 输出和检查

```sh
python3 scripts/build_jimeng_boards.py WORK/C02-plan.json --output-dir DELIVERY/C02 --font CJK_FONT --reference-image-count 2
```

宫格固定3列×3行，每页9槽，仅末页可空；列数和格数不可改为2/6/4。详细表默认每页3镜，可用`--table-page-size 1`提高阅读性，但表页、宫格页和`--reference-image-count`（默认1）合计不得超过9；超预算在写文件前报错。超大页需精简冗余文字或调整表分页，不缩字、不把宫格改少槽提前分页。输出目录存在时报错，使用新版本目录。

表图固定十列，与用户截图一致：时间 / 镜头编号 / 景别 / 摄像机角度与运动 / 画面内容 / 演员动作 / 产品展示重点 / 台词/旁白 / 音效/音乐 / 字幕。scene/lighting/states进入画面内容，action/environment进入演员动作（含动物/物件），purpose/constraints/reference/transition进入产品重点列；camera/parallax进入机位列，shot_size、dialogue独立成列。旧13字段计划需补齐这两项，不从字幕猜旁白。所有执行信息保留，内部planning_notes不渲染。

仅输出连续编号的`01-C02-shot-table-01.png`等表页与后续编号的`02-C02-storyboard-01.png`等宫格页；有多页时编号连续递增。每页使用正方形画布、不裁切拉伸内容，像素高度≥350。分页后的实际文件顺序决定TXT中的上传引用。保持文字可读，空白过多时可调整每页镜数；内容过高导致方形画布超资源上限时要求拆页，不悄悄缩字。

共同输入快照、SHA-256、表行/状态格映射、9槽占用信息与上传预算在函数返回值中，**不写`boards-manifest.json`**。CLI仅打印输出图片清单。后续将该段draft.txt和已核合格的精选产品图片放入同一目录，素材图继续使用下一个上传序号。不要将临时计划JSON、原始帧目录或预览文件复制进交付。

逐页看图并对照TXT/CSV及README映射，检查编号、秒段、格下说明、插入次数、字幕、文件版本、字体和缩放可读性。运行`check_delivery_package.py`检查所有上传图，产品图也必须满足高度≥350与宽高比0.6–1.6，优先1。跨C-ID不重置S-ID、不重复计时；`.draft.txt`为固定命名，实际齐备状态见README，缺帧不能拿空白图交终稿。
