# 需求澄清与商品事实承接

成品套图为默认主要入口，先读[套图承接与导演讨论](image-campaign-handoff.md)。缺原项目记录不阻塞启动，不强制整包原始图；先提供两套具体镜头方案，弹窗逐轮细调。安装优先AI演示，未知步骤逐项待核，不默认必须实拍。

## 有已有图片策略时

读取用户指定成果，不遍历无关历史项目。优先检查：

| 输入 | 承接内容 | 不自动承接 |
| --- | --- | --- |
| 当前会话、`discovery.md` | 已确认 SKU、变体、受众、选择/委托、未决事实 | 失效版本或其他 SKU 的回答 |
| `evidence-ledger.md`、实拍和规格 | 能覆盖本 SKU 的 P 事实、范围、出处和限制 | 竞品主张、未经验证的 AI 图细节 |
| `design-strategy.md`、竞品/评论记录 | 买家问题、信息优先级、确实观察到的视觉启发 | 评论代表我方性能、未读来源的结论 |
| `layout-decisions.md`、逐图 Brief | 用户认可的风格、配色、主体/道具身份、尺度依据 | 静态布局强行充当动作、方图/A+画布限制 |
| 已完成套图、`set-refresh-map.md` | 旧图来源、清楚区域、排版与应保留关系 | 旧图渲染出来的结构就是真实结构 |

保留原事实 ID 和实际来源定位，例如 `P-07 → evidence-ledger.md §… → 原始照片/规格`，新增事实可用 `VP-01`。发现文档与照片、尺寸或用户当前说明冲突，列明冲突并澄清，不以“继承”掩盖矛盾。素材路径失效时仅索要当前镜头必需的文件。旧策略里已经确认的事实无需整套重问；新视频展示新的部位/动作时才补对应证据。

## 最小事实表

每条事实记录：对象/部位、值或可观察描述、来源与定位、用户确认情况、适用条件、允许支撑的镜头、不能推出的结论。区分：

- **商品事实**：SKU、颜色、构造、尺寸及测量端点、套装数量、随货物、真实使用方法。
- **视觉参考**：构图、环境、配色、节奏、运镜；不能给商品补功能和外观。
- **创意提案**：可以设计的背景、光线、道具、叙事和镜头。写为 proposed/confirmed/delegated。
- **待证信息**：不能见到的背面、接口、花瓣纹理、茎杆分叉、安装方法、耐水性等，依赖镜头暂缓。

花木先注明活体/鲜切/干燥保鲜/仿真类别；涉及操作时再补该操作的事实：可动部位、工具与支撑、是否需组装/整形、允许/禁止的清洁介质及收纳条件。记录出处和适用 SKU，不把这些变成所有项目必填问卷。用户说“低维护”但未给方法时，只记录定位，不能直接排水洗/喷剂镜头；需要时请求随货说明或同款实际操作。

实拍证明可见外观，不能仅凭照片判定材料成分、耐候寿命或使用功效。规格/用户明确事实声明可提供对应依据，但明显自相矛盾时仍要澄清。竞品和评论说明市场问题，不证明我方解决了问题。AI 生成的关键帧与前期视频是派生产物，不用于反向验证 SKU。

用户提到有照片但本轮尚未提供/无法访问时，可以完成其授权的文字设计，身份锁只写用户已给出的属性与未来输入要求；不声称看过图，不填叶色、疏密、花纹或盆形。文字分镜完成与商品画面/AI输入待补分别记录，不因未收照片把整个文字任务标为未完成。

## 多轮提问：下一答能改变什么

第一轮先检查已有资料；简短复述已理解的目标与事实，问当前最影响方案的未知项。用户只说“做个产品视频”时，优先确定使用位置/观众、观众看完应理解什么、期望时长与画幅；这些已知时直接进入表达方向。

后续问题由实际答案触发，通常分为以下层次，但不是固定轮数或必填清单：

| 需要收敛的内容 | 合适问法/处理 |
| --- | --- |
| 用途与目标 | 商品详情页、Sponsored Brands、Sponsored Products 或站外短视频？先确定展示、布置、操作或维护中的首要任务，不同版位按 [适配说明](amazon-placements.md) 核对。 |
| 主信息 | 从有依据的卖点中提出有区别的选择，说明它会改变哪些镜头；不要让用户自己写完整广告策略。 |
| 表达路径 | 对比“环境展示”“真实操作”“细节质感”等适合本 SKU 的方向，写出开头事件与后续推进；不固定三选一。 |
| 创意尺度 | 写实或风格化、节奏、参考片的具体借鉴维度、人物/手部、场景道具、避用元素；已明确委托可自行决定。 |
| 文字与声音 | 文案由用户提供还是代拟？字幕语言，旁白/人物对白/音乐/环境音的需要与制作方式；无声/无字也是完整方案。 |
| 交付与制作路线 | 默认16:9、每条片段4–15秒、新项目总量通常约30秒（花卉默认15秒）的连续提示词，按段位顺序连接；先核对每段时长/参考/声音和接缝能力。实拍可作操作参考，混合后期按用户选择。未知能力/未来锚帧标依赖，不妨碍先写内容草案。 |

弹窗选择项应说明对结果的影响，例如“慢节奏环境展示：先交代摆放效果，再看细节”与“实际使用演示：需要清楚的操作与连接部位资料”。少用“高级/普通/其他风格”这种不可执行选项。用户明确要直接出方案时，列出采用的设计假设后推进，不以多轮流程强制阻塞。

每轮回答后更新记录，指出影响的镜头，继续解决下一处实质不确定性。没有必要反复确认所有文案或每个镜头；准确事实、用户锁定措辞和未被委托的关键选择不得越过。

## 计划镜头尺度决定补图需求

先查看实际文件。全景可用的图，不一定支持花瓣/接口特写；压缩、锐化或超分辨率不会新增真实证据。对当前需展示的部位，检查：轮廓、纹理、连接关系、颜色、遮挡和必要尺寸是否可辨。

发现影响执行的未知信息时请求最小补充；用户已明确暂无资料或先要草案时直接记录缺口，不再问同一个问题。例如：

> S03 要展示花头到茎杆的连接，目前旧图这一处被文字盖住。请临时补一张同款同色、对焦清楚的连接处实拍，保留旁边一片叶子作为位置参照。S01、S02 的全景部分可继续制作。

事实可以文字回答的，通过弹窗询问；需看纹理/结构时在对话中索要图片。一次清楚说明缺什么、拍什么部位/角度、影响哪一镜。不能从竞品花材、其他变体或模型“常识”补齐；不要要求与本片无关的全角度大包。

原计划依赖未知背面时，可以提供只展示已知正面的小幅横移方案；用户接受/委托后更新方案，而非一边索要背面一边交付环绕镜头。

## `video-brief.md` 的续作状态

保留以下信息即可，不复制整套来源正文：

- 项目/SKU/变体、当前版本、输入资料位置、继承的策略版本。
- 发布位置与目标市场/语言、核心信息、目标总长、画幅、当前范围。
- 交付方式 `connected-clips`（默认每条4–15秒、新项目总量通常约30秒（花卉默认15秒）、16:9）；用户指定的单次整片/其他条数另记。记录分镜是否确定、详细分镜表状态；不生成故事板、各段声音/字幕、能力来源及账户待核项。
- 目标版位的规则来源/核对日期、展示/使用/维护任务选择、逐镜实拍/AI/混合路线；有操作时的允许/禁止条件。
- 商品事实与出处；商品身份锁；随货物/道具/其他产品的区分。
- 已确认/委托的创意与依据；工作假设；待答事实与受影响镜号。
- 总体视觉锁：环境、产品尺度、配色、光线、人物/手部身份、道具、文字与声音路线。
- 当前阶段、下一步、已完成画面/片段、被新证据影响的交付。

产品身份锁跨镜不变。允许变化另记：同一实物可做的真实造型整理、镜头、背景、经证实的操作等。风格化背景也不授权花材增减或结构变形。
