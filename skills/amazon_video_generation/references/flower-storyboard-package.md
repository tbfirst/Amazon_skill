# 花卉分镜板、分析说明书与交付

## 两类图片都上传即梦

用户2026-11-01明确：主要上传详细分镜表图片、宫格故事板图片、提示词及部分产品图。新项目的四项核心交付是分镜表PNG、宫格故事板PNG、完整/分段中文TXT、中文分析说明书；表图不再只是供人审阅的附件。草木共用此交付标准，摄影内容仍按草木路线。

**详细分镜表 `C01-shot-table-01.png` 等。** 每镜一行，左列标S-ID、C-ID、全局/本段起止与时长、对应格号；右侧按场景与相机、动作与空间、文案与衔接分组写全执行信息。必要的步骤、方向、时间、次数和约束必须在PNG上读得到，不能用“详见MD”省略。长内容用自动换行和分页，不把超宽长表缩成小字；操作复杂时减少每页镜数，必要时另做同S-ID续页并标清“续”。MD/CSV保留可编辑原始数据。

**宫格故事板 `C01-storyboard-01.png` 等。** 每格使用实际选定商品画面，按左到右、上到下顺序排列；每格图片下方固定放：S-ID、C-ID、局部/全局秒段、状态格号，以及1–2句简短中文说明。说明具体到“什么主体在什么位置/做什么、此格是什么状态”，可加简短运镜方向，不能只写“高级感、细节、场景”。文字位于画面外的格下说明区，不能压住商品。视频画幅用于每格画面，整张板可因说明区加高；不强行做九宫格，按状态数选择2–3列与分页。

S-ID是镜头，不是格子序号。同镜多状态使用`S05/start`、`S05/key`、`S05/end`，表里S05列出这些格号；各格仍共享该镜秒段，不把三格算三镜或重复累计时长。状态说明要能区分起态、过程与结果，不能复制同一段空泛短语。插删、分页或进入C02不重编号；镜头播放顺序以数据列表顺序为准，编号允许有空缺。

每C-ID从**同一份镜头计划**同时导出表和板，版本一致。分段时每段各有对应表、板、执行词与产品图清单，C02局部时间从0起、全局偏移保留，S-ID沿用全片。全片总览可另交但不默认占每段上传槽位。

两类图片均为全能参考中的导演/叙事参考，不默认设为首帧。提示词明确逐镜全屏呈现，只显示明确指定的成片字幕，不把表格、宫格边框、镜号、中文说明或箭头生成进视频。精选清晰产品图承担身份参考，小格不承担唯一身份依据。

## 复用→补帧→排版→目视检查

1. 先查看所有拟使用的最终图，确认SKU版本、图内文字和主体可用区域。已有图能表达该镜关键状态则复用；单纯改变摄影景别不必全部重画。
2. 按[动态导演规则](dynamic-flower-direction.md)列每镜缺口。关键动态镜至少两个有意义的状态/视角：相机环绕/空间尺寸用不同机位起终态，主体落点不变、背景透视合理改变；细节用接触/风动前后状态；分组展开用起态＋分组关键态＋终态；逐次插花用已有花材起态、累积中态、第三次落位终态，表与词展开3次操作；成束模式用手中整理态、整束接近瓶口/插入态和落位终态，不能只给手持与最终成品而省略整理。展示台开场记录背景ID、SKU身份参考、配色改动及相机起终视点。不是强制每镜三帧，按复杂度选；不能用同一图片大小裁切冒充机位变化，只有成品图不能证明多个插花动作已经设计完整。
3. 需要新照片式画面或精修时读取 `imagegen`，调用内置图像生成/编辑工具，实际附上已查看的商品参考。说明目标S-ID、动作状态、不能改变的商品特征、可变构图和背景。工具失败不能声称已补图，也不能悄悄换付费API。只缺画面且事实充分时直接在已授权范围补，不重复询问是否允许正常生图。
4. 保存真实输出到项目 `storyboard/frames/`，不只引用工具临时默认目录。记录来源/输入角色/生成词、对应镜头和版本；生成的新视角标视觉推演，核对商品外观，不以它补事实。
5. 新项目用 `scripts/build_jimeng_boards.py` 从同一镜头计划同时排出详细表和宫格板；旧项目仍可用 `scripts/assemble_storyboard.py`。程序只做几何排版和标签，不生成商品。图片像素编辑仍走图像工具；这里排版是已选画面的文档组装。
6. 目视检查两种PNG的顺序、排格、商品特征、动作状态、文字可读性、边界/留白和截断警告。错的面板定向改，其他面板检查是否漂移。不能以脚本通过代替看图。

每帧状态：`reused-reviewed / generated-reviewed / needs-revision / pending / stale`。无产品图时仍可交研究和文字结构草案，但视觉板状态必须pending，不能拿参考片产品冒充用户商品。

## 同源排版工具

详读[同源镜头数据与排版](jimeng-board-schema.md)。每段准备一份`C01-plan.json`，由完整镜头表按C-ID筛选并计算局部时间，不能手工维护互不关联的table-plan和board-plan。

```sh
python3 scripts/build_jimeng_boards.py PROJECT/C01-plan.json --output-dir PROJECT/storyboard/C01-v1 --columns 3 --grid-page-size 6 --table-page-size 3 --font CJK_FONT
```

替换实际路径。工具输出真实PNG与`boards-manifest.json`，记录共同输入快照/哈希、镜号、格号、说明、表内明细与图片哈希。目标目录须为新版本；不覆盖旧交付。它验证时间连续、编号唯一、必填信息和格下说明，再从同一输入生成两类图；不核实文字内容是否正确，也不自动检查TXT或跨C-ID一致性。

两类PNG都要打开检查，按用户实际上传预览的缩放查看文字；必要时减少单页镜数或格数。关键动作与编号不能截断。默认中文字体须支持中文；出现方框换真实CJK字体。局部时间从0到本段总长，跨段全局时间接续另行检查。旧排版器保留兼容，不作为新上传包的双图同源方案。

## 项目输出

默认 `outputs/amazon-video/<sku>/<revision>/`，核心文件：

|文件|内容|
|---|---|
|`jimeng-full-prompt.txt`|整片自足中文提示词，包含顺序、引用角色、字和声音；说明它是本入口执行词还是总脚本|
|`analysis-manual.md`|中文分析说明书：片长与分段选择、模块理由、卖点依据、用图原因、每镜任务、风格/转场、S-ID/格号对照及各段附件顺序、入口操作、接缝、错字修正、验片重点|
|`storyboard/C01-v1/C01-storyboard-01.png`等|真实画面、稳定格号与格下中文说明的宫格故事板|
|`storyboard/C01-v1/C01-shot-table-01.png`等|上传即梦的详细分镜表图片；与宫格板使用同一镜头数据|
|`shot-list.md`、`shot-list.csv`|完整详细导演表，CSV使用UTF-8 BOM|
|`input-map.md`、`video-brief.md`|素材事实与最终版本、弹窗决定、未决项|
|`jimeng-upload/`、`jimeng-upload-manifest.json`|精选实际附件与有序角色映射，不要求用户自行从11张里猜|
|`overlay-copy.csv`|准确英文、数字/单位、来源、S-ID、时间和位置|
|`README.md`|按操作顺序链接实际文件，当前可执行状态、应复制哪条词、上传哪些图|

分段才增加：`jimeng-prompts/C01.txt`、`C02.txt`、各段对应的分镜表PNG和宫格故事板PNG、`continuity.md`；总脚本保留。必要事实或附件未齐的执行词用 `.draft.txt` 并列具体依赖，不能在可复制终稿中残留花型/数字/引用占位符。

导演表至少含：顺序、S-ID、C-ID、场景ID、全局起止、局部起止、出镜时长、生成任务长度、景别/角度、主运镜/起终点/速度、主体动作、环境响应、空间参照与视差、起中终状态、灯光、信息目的、事实来源、参考文件、图内文字、声音、转场和状态。插花另记模式（sequential/bundle）、计划插入次数（默认3/成束1）、起态已有花材、各次颜色/花型、手中整理动作及累计器内状态。开场另记背景ID、室内/室外、配色适配和商品主位。字段可按可读性分组，不必将整条提示词塞进超宽表格；在表后附对应执行词块，与TXT逐字一致。

上传清单每附件包含实际文件、角色、顺序、来源版本与SHA-256；每C-ID包含执行词路径、所用分镜表与宫格板的全部页、目标/生成/保留长度、附件、已核入口和pending依赖。建议每段附件顺序为详细表各页→宫格板各页→精选产品身份/细节图；按实际入口调整后同步TXT，不能假定TXT是图片附件，操作说明区分“上传哪些图”与“复制哪段词”。说明书是给用户的解释，不默认占图片参考槽位。参考数量未知时列待核；槽位不够时先移除重复参考、减少冗余画面，必要时调整分页或分段，不默默删掉表/板或牺牲可读性。已过时图片不仍标最终；将旧版归历史，不覆盖原文件。

采用[逆推模板库](reverse-video-prompts.md)时，说明书补充来源片/镜号/时间码、借用的叙事或镜头方法、本SKU替换项、与原片不同的用户要求，以及音景是已核观察还是设计建议。原片英文报告可作参考附录，不能代替当前SKU的完整中文TXT、实际分镜PNG和上传清单。

## 交付前检查

- 时间从0连续到选定总长，无重叠/空洞；局部时间与全局偏移一致。每C-ID生成长度≤实际上限，保留合计不超生成长度。
- 表与板来自同一计划版本；逐项对照每镜的表行、所有状态格、TXT中的S-ID、秒段、动作、文案与参考角色。无漏镜、孤立格、错误重编号或旧版本混入；格下每段短说明与对应动作状态一致。
- 主提示词含全片，分段词自足，C02无“同上”；图、表、词的镜号/顺序/文案/引用一致。
- 每个卖点与尺寸可追到本SKU；附加花器/配景不暗示随货；自动展开是陈列还是实际结构已明确。
- 环绕和尺寸段均为相机绕行，花器/整束不自转；近远背景视差有明确参照。尺寸图只借鉴空间表达，不继承参考商品的数值或折叠机构。
- 细节有适合材质的轻摆/接触响应或有理由的真实侧向观察；逐次插花默认3次可辨认落位松手，或成束模式完整显示手中整理后1次入瓶；起态已有花材、颜色/花型与累积状态可追踪；固定成品有合理替代。
- 各场景内部有真实机位位移/透视或可见事件，不是静图缩放轮播；关键动态参考有不同状态，提示词明确中间过程。生成后另查视差、接触和动作次数，未生成不能声称动态验收通过。
- 图片实际存在、已查看、商品一致；输入图不等于唯一首帧；分镜板的说明不会被计划为成片文字。
- 字与数字正确、音乐衔接有计划；静态图合格不等于动态动作合格。
- 检查脚本通过只证明它覆盖的运镜/时长规则。若还没在即梦生成，清楚说“前期包完成，视频未生成/未动态验收”。
