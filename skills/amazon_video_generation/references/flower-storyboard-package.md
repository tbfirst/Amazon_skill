# 分镜图片、精简目录与交付（所有商品共用）

## 两类图片都上传即梦

用户2026-11-01明确：主要上传详细分镜表图片、宫格故事板图片、提示词及部分产品图。v5.5将它们按C-ID集中在各段文件夹，根目录仅留分析说明书、README和分镜CSV。所有品类共用此交付标准，具体摄影内容按通用或花卉/草木路线。

**详细分镜表 `01-C01-shot-table-01.png` 等。** 每镜一行，采用用户样图的横向十列表格与清楚网格线、深色底浅色字：时间、镜头编号、景别、摄像机角度与运动、画面内容、演员动作、产品展示重点、台词/旁白、音效/音乐、字幕。时间列包含全局/本段起止，镜号列包含稳定S-ID与状态格号，C-ID置页眉；画面列含光线与状态，动作列含主体/动物/道具动作及环境响应，重点列含本段附件与连续性/接镜。无人镜明确无人及实际主体动作；旁白与字幕分别列出，不把字幕误当台词。必要的步骤、方向、时间、次数和约束必须在PNG上读得到，不能用“详见MD”省略。长内容用自动换行和分页，不把超宽长表缩成小字；操作复杂时减少每页镜数，单行过长时精简冗余描述；当前排版器不支持同S-ID跨页续行，不伪造重复镜号绕过验证。CSV保留可编辑原始数据。

**宫格故事板 `02-C01-storyboard-01.png` 等。** 每格使用实际选定商品画面，按左到右、上到下顺序排列；每格图片下方固定放：S-ID、C-ID、局部/全局秒段、状态格号，以及1–2句简短中文说明。说明具体到“什么主体在什么位置/做什么、此格是什么状态”，可加简短运镜方向，不能只写“高级感、细节、场景”。文字位于画面外的格下说明区，不能压住商品。视频画幅用于格内画面；整张板固定3×3九个等尺寸槽位，每槽包括图位与格下说明区。按顺序填满当前页9槽后才能新开一页；最后一页可留空槽，空槽不放伪造图/重复填充/镜号，不为凑满增加镜头。整张板优先正方形。

S-ID是镜头，不是格子序号。同镜多状态使用`S05/start`、`S05/key`、`S05/end`，表里S05列出这些格号；各格仍共享该镜秒段，不把三格算三镜或重复累计时长。状态说明要能区分起态、过程与结果，不能复制同一段空泛短语。插删、分页或进入C02不重编号；镜头播放顺序以数据列表顺序为准，编号允许有空缺。

每C-ID从**同一份镜头计划**同时导出表和板，版本一致。分段时每段各有对应表、板、执行词与产品图清单，C02局部时间从0起、全局偏移保留，S-ID沿用全片。不另生成全片总览板；全片结构写进分析说明书和CSV。

两类图片均为全能参考中的导演/叙事参考，不默认设为首帧。提示词明确逐镜全屏呈现，只显示明确指定的成片字幕，不把表格、宫格边框、镜号、中文说明或箭头生成进视频。精选清晰产品图承担身份参考，小格不承担唯一身份依据。

## 上传文字与内部记录分开

表图、格下summary和TXT都直接进入模型，内容只写本SKU、实际本段附件及要发生的画面/声音。“详细完整”指已决定的可执行内容，不包括研究推理或待核问题；依赖未齐时保留草案状态，不把未知项画进可上传终稿。`details.reference`只放本段文件名/图片序号和身份/结构绑定；事实来源、模板ID/时间码、研究边界、失败原因和未核事项留分析说明书/CSV内部字段，不画进上传表。`details.constraints`写与本SKU直接有关的限制，不复制原片禁用清单。`planning_notes`可暂存内部决策，排版器不渲染；不是新增交付文件。

## 复用→补帧→排版→目视检查

1. 先查看拟用产品/最终图，确认SKU版本、文字与主体区域。产品原图的杂乱背景不沿用；按[文字背景库](display-background-library.md)换干净场景，已选干净最终场景可复用。单纯改变摄影景别不必全部重画。
2. 所有商品先按[物理连续性](physical-continuity.md)列每镜缺口：同一实体/活动件的起中终状态、真实连接、接触支撑及遮挡恢复；相机路径应在场景可达区域且有角度依据。关键动态按需要选择至少两个有意义的状态/视角。以下是flowers分支的条件示例，不是所有商品必做：相机环绕/空间尺寸用不同机位起终态，主体落点不变、背景透视合理改变；细节用接触/风动前后状态；分组展开用起态＋分组关键态＋终态；逐次插花先从选定完成态倒推基础花材及3次补入，使用同源起态、关键操作/落位状态与完成态，表与词展开每次操作；成束模式用手中整理态、整束接近瓶口/插入态和落位终态，不能只给手持与最终成品而省略整理。展示台开场记录背景ID、SKU身份参考、配色改动及相机起终视点。不是强制每镜三帧，按复杂度选；不能用同一图片大小裁切冒充机位变化，只有成品图不能证明多个插花动作已经设计完整。
3. 需要新照片式画面或精修时读取 `imagegen`，调用内置图像生成/编辑工具，实际附上已查看的商品参考。说明目标S-ID、动作状态、不能改变的商品特征、可变构图和背景。工具失败不能声称已补图，也不能悄悄换付费API。只缺画面且事实充分时直接在已授权范围补，不重复询问是否允许正常生图。
4. 保存实际需要上传的画面到对应C01/C02目录；仅用于拼宫格的中间帧放交付目录外的临时工作区，不额外导出frames目录。说明书记录来源/角色、对应镜头和版本；实际上传图不携带内部研究注释；生成的新视角标视觉推演，核对商品外观，不以它补事实。
5. 新项目用 `scripts/build_jimeng_boards.py` 从同一镜头计划同时排出详细表和宫格板；旧项目仍可用 `scripts/assemble_storyboard.py`。程序只做几何排版和标签，不生成商品；每镜details新增shot_size（景别）和dialogue（台词/旁白）两项，旧计划需补齐后重排。图片像素编辑仍走图像工具；这里排版是已选画面的文档组装。
6. 目视检查两种PNG的顺序、排格、商品特征、动作状态、文字可读性、边界/留白和截断警告。错的面板定向改，其他面板检查是否漂移。不能以脚本通过代替看图。

制作前按[终态与运动规则](terminal-state-and-motion.md)核对目标造型、逐步来源/落位、机位的空间证据、驱动与响应及手持支撑。同一镜只用start/key/end；更多必要状态结合真实剪辑点分镜或调整参考方案。每步落位必须接得上下步，终态对照选定成品的数量和层次，不能靠最后换图补满。

每帧状态：`reused-reviewed / generated-reviewed / needs-revision / pending / stale`。无产品图时仍可交研究和文字结构草案，但视觉板状态必须pending，不能拿参考片产品冒充用户商品。

## 同源排版工具

详读[同源镜头数据与排版](jimeng-board-schema.md)。在交付目录外的临时工作区为每段准备一份`C01-plan.json`，由完整镜头表按C-ID筛选并计算局部时间，不能手工维护互不关联的table-plan和board-plan。

```sh
python3 scripts/build_jimeng_boards.py WORK/C01-plan.json --output-dir DELIVERY/C01 --columns 3 --grid-page-size 9 --table-page-size 3 --reference-image-count 2 --font CJK_FONT
```

替换实际路径。工具仅写入按上传顺序编号的正方形PNG；共同输入快照、镜号、格号、说明和哈希只作为内存返回值，不另写JSON清单。目标C01/C02目录须尚不存在；先生成PNG，再写该段提示词并复制已核的产品图。新版使用新的交付根目录，不覆盖旧交付。它验证时间连续、编号唯一、必填信息和格下说明，再从同一输入生成两类图；不核实文字内容是否正确，也不自动检查TXT或跨C-ID一致性。

两类PNG都要打开检查，按用户实际上传预览的缩放查看文字；必要时减少表页镜数或精简格下冗余文字；宫格仍固定九槽，不能提前续页。关键动作与编号不能截断。默认中文字体须支持中文；出现方框换真实CJK字体。局部时间从0到本段总长，跨段全局时间接续另行检查。旧排版器保留兼容，不作为新上传包的双图同源方案。

## 每段最多9张：先预算后生成

`表页数 + ceil(本段实际状态格数 / 9) + 产品/细节/场景/锚帧等独立图数 ≤ 9`，对C01、C02分别计算，共享图在两段各占一张。每个PNG/JPEG算一张，九格板整体只算一张；空槽不算状态，不用空页占名额。README按实际上传序号给总数及角色。

先保留可读表页、完整九槽板及必要商品身份/结构图，再删重复或无信息增量的参考；可把适合的状态放入宫格，但不能把关键身份细节缩小到看不清。不得靠缩小字、删关键过程、用一张巨型拼图逃避预算，或增加C03绕过上限。排版仍超预算时调整镜头/冗余素材；若损害已选内容，弹窗给具体取舍。

排版器`--reference-image-count`填写除表/板外所有计划上传图片数（默认1），超9在写文件前报错；完成复制后运行交付校验，按实际文件数再核一次。该参数是预算，不会生成产品图或自动证明素材齐全。

## 唯一交付目录

默认`outputs/amazon-video/<sku>/<revision>/`，双段交付严格采用下列结构。括号说明不是实际文件，图片页数按内容决定：

```text
<revision>/
├── C01/
│   ├── C01.draft.txt
│   ├── 01-C01-shot-table-01.png
│   ├── 02-C01-storyboard-01.png
│   └── 03-product-identity.png
├── C02/
│   ├── C02.draft.txt
│   ├── 01-C02-shot-table-01.png
│   ├── 02-C02-storyboard-01.png
│   └── 03-product-identity.png
├── 分析说明书.md
├── README.md
└── shot-list.csv
```

- 单段仅C01；不为了凑目录生成空C02，也不默认增加C03。若实际入口不能用一/两段完成既定总长，弹窗解决时长或入口选择后再交付。
- 每段目录**平铺**本段唯一`.draft.txt`与所有需要上传的图片，不建images子目录。共享产品图各复制一份至两段目录，用户不需要跨目录寻找。图片使用PNG或JPEG，名称以连续`01-、02-…`排序；每段从01开始，先表页、再宫格页、后精选产品/细节/场景参考，TXT按同一实际顺序引用。
- `.draft.txt`是用户指定的固定文件名，不等同于内容缺失。正文齐备也不改名或额外导出终稿。缺事实/缺图片/未核入口时，README逐段写明待补项；不得在可执行正文里用未知花型、尺寸或附件占位符冒充已齐备。
- 仅有上述交付：不另写`jimeng-full-prompt.txt`、`shot-list.md`、`video-brief.md`、`input-map.md`、`continuity.md`、`overlay-copy.csv`、JSON清单、全片总览图、HTML、ZIP或其他报告。必要的计算/排版中间数据在内存或交付目录外的临时区；不为替代被取消的交付而另建一套旁路文档。

## 三个根文件分别写什么

**分析说明书.md**：商品事实和来源、售卖边界、素材最终版本/原图与生成图身份、必要弹窗决定、片长/分段与模块理由、每镜目的、关键实体的身份/数量/连接与允许状态变化、空间可达性/动作/遮挡/转场设计、全局时间线、分段接缝、字幕与音乐修正方案、推演缺口及验片重点。借鉴参考片时记来源片/镜号/时间码、借用方法、本SKU替换项和已核/设计音景；不单独导出研究附录。

**README.md**：按实际操作顺序解释C01/C02各上传哪些图、复制哪个draft.txt、已核入口和时长、目标/生成/保留范围、S-ID和格号怎么对应；列每张附件的相对路径、顺序、角色、来源版本、像素宽高和宽高比，必要哈希直接列此表。正文、素材、设置、视频生成、动态验收分别记录状态；当前可执行与待补项明确。说明图片为参考图，边框、镜号、格下说明和留白不进视频；正方形上传图不代表方形视频。

**shot-list.csv**：UTF-8 BOM的全片详细分镜源表。至少含顺序、S-ID、C-ID、场景ID、全局起止、局部起止、出镜时长、生成任务长度、景别/角度、主运镜/起终点/速度、主体动作、环境响应、空间参照与视差、起中终状态、灯光、目的、事实来源、本段参考文件、内部事实/研究来源（与上传文字分列）、关键部件/道具身份及连接、对应状态格号/简述、成片文案/单位/时间窗/位置、声音、转场和状态。需倒推的操作另记目标完成态来源、各次增减组件/落点与前后状态、未操作部分及终态审阅；插花另记模式、次数、基础花材、各次颜色/花型和手中整理。多场景另记用途/空间差异、真实驱动与次级响应；手持细节记录支撑、转向及允许的材料响应；开场另记背景ID、室内外、配色与商品主位。不再附重复的提示词全文，正文以各段draft.txt为准。

## 所有上传图片的统一规格

对C01/C02内**每张图**逐一检查，包括表图、宫格、产品图、细节图、场景图、锚帧：实际解码/EXIF校正后的高度≥350px，`0.6≤宽÷高≤1.6`（含边界），优先1:1。此为本用户明确的交付要求，不凭此宣称平台所有入口均采用该限制。整张16:9上传图比例约1.778，不合格；视频及宫格内部镜头仍可16:9。

表/宫格优先在方形画布中重排、分页，按需留白，保持字号、画面比例与商品完整，不将已有超宽图强行压缩成方形。工具用不裁切的正方形画布保留全部图文；若单页过高或说明太密，减少表页镜数或精简宫格冗余说明（宫格仍固定九槽，不能提前续页）。产品图优先选已有合格清晰版本；需改变构图/扩画布时按imagegen工作流处理并目视核对，不随意截掉花材、数量证据、容器或尺寸端点，不拉伸主体。低清源图不能仅扩大画布冒称细节合格。

```sh
python3 scripts/check_delivery_package.py DELIVERY
```

校验只读，不补图、不自动删文件、不新增报告。检查唯一文件层级、提示词存在、CSV基础结构/BOM、图片解码、EXIF方向、全部图片尺寸/比例和上传序号。只证明目录与图片格式达标，不代替表/板/词对应关系、商品真实性和文字可读性的目视检查。若素材缺失，保留明确的未齐备状态，不能用占位图使校验假通过。

## 交付前检查

- 时间从0连续到选定总长，无重叠/空洞；局部时间与全局偏移一致。每C-ID生成长度≤实际上限，保留合计不超生成长度。
- 表与板来自同一计划版本；逐项对照每镜的表行、所有状态格、TXT中的S-ID、秒段、动作、文案与参考角色。无漏镜、孤立格、错误重编号或旧版本混入；格下每段短说明与对应动作状态一致。
- 整片结构在说明书/CSV完整可追，分段draft.txt自足，C02无“同上”；图、表、词的镜号/顺序/文案/引用一致。
- 每个卖点与尺寸可追到本SKU；附加花器/配景不暗示随货；自动展开是陈列还是实际结构已明确。
- 全品类检查相机可达路径、真实结构与合理透视；操作组件/道具同一身份、连接和数量变化有原因，遮挡后状态可追。正面读形按实际机位判断，不把所有梯形投影判错。flowers环绕/尺寸段沿用相机绕固定花器及背景视差规则；不迁移参考数值/机构。
- flowers细节有适合材质的轻摆/接触响应或有理由的真实侧向观察；逐次插花默认3次可辨认落位松手，或成束模式完整显示手中整理后1次入瓶；起态已有花材、颜色/花型与累积状态可追踪；固定成品有合理替代。
- 各品类场景用途与空间有差异，生活场景优先用途相关的画内微动作及可见响应，只有合适的理由才仅用真实机位位移/透视，不是静图缩放轮播或正面纸片摇摆；驱动、支撑、柔性部分及可见光影响应一致，稳定光源不强制闪动；关键动态参考有不同状态，提示词明确中间过程。生成后另查视差、接触和动作次数，未生成不能声称动态验收通过。
