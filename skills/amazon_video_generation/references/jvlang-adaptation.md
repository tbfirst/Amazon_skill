# 从 jvlang 服装故事板迁移的方法

本轮于 2026-10-27 只读检查用户指定 `/mnt/e/jvlang` 源码。以下说明已迁移的设计与保留的差异；本技能无需启动 jvlang、调用其接口或读取其配置。属于源码分析，不是服装系统的端到端生成实测。

## 分镜生成

| 参考实现 | 采用的方法 | 花卉植株中的落点 |
| --- | --- | --- |
| `jvlang-ai-python/app/routes/storyboard.py`，`draft` 中的大纲/导演意图、角色/场景清单及结构化响应 | 先锁整体事件，再逐镜扩写；场景/主体有稳定标识，画面、主体动作、相机分列 | `video-brief.md` 内的事件大纲、SKU身份锁、场景/道具清单；确有手部才加人物信息 |
| 同文件 `generate-frame` 的 `prev_same_shot` 分支 | 同镜后续状态与跨镜承接分开，以实际上一帧作锚点 | 插瓶、整形、装配的具体动作进度；正面单图不能借该机制补造背面或结构 |
| `features/Storyboard/gridGenerationStore.ts` 的批次、状态与 `shotsSnapshot` | 候选与其生成版本绑定，失败可局部重做，旧版本结果留在旧版本 | 在 `frame-prompts/`、参考映射中存候选记录；仅选定帧进入 plan，不需要复制 Web 后台任务系统 |
| `features/Storyboard/Stage2Storyboard.tsx` 的稳定 `shotNo` 与可编辑结构 | 修改局部镜头时保持关联，时长与总计划一致 | 沿用 S-ID，调序/删镜不把旧帧误配给新镜；时序由现有拼板工具校验 |

不迁移服装廓形/面料、模特人脸与转身展示模板；植株主锁是花叶、茎杆、分叉、数量、轮廓、盆底/挂点和真实支撑。固定镜数等于宫格数、用缺省内容补空格、为了生成而截断镜头，均不成为本技能行为。相机环绕、枝条弯折和清洗须独立有商品依据。

## 宫格拼接

| 参考实现 | 采用的方法 | 本工具的差异 |
| --- | --- | --- |
| `features/Storyboard/storyboardSheetCanvas.ts` 的 `wrapField`、`captionLines`、`rowCapH` | 中文按实际字宽换行，字段省略提示，同行按最大说明高度对齐 | Pillow 实现可选 `caption`，说明在画面之外；旧输入保留紧凑模式 |
| `features/Storyboard/Stage4Layout.tsx` 的 `exportStoryboard` | 格子说明应对应来源画面的镜头快照，不能随当前表无条件变化 | 候选生成记录与拼板计划复核；`--manifest` 保存排版时快照和源帧哈希，生成时来源仍需另外记录 |
| `features/Storyboard/layoutCompose.ts` 的槽位引用 | 最终选择明确引用源图片和目标位置 | 本项目直接按 `S-ID/state/file` 选择完整干净帧，按时间线顺序排版；不按文件名排序或候选序号猜测 |

不复制整张 AI 宫格的等分裁切：网格不齐会串格，高树、垂藤、花环和散枝易丢顶部/底部/端点。v3默认输出详细文字分镜表，不生成故事板；用户另行要求关键帧时再处理，已有独立帧拼板只等比缩放留边。不默认固定九宫格、3:4、空白占位或把整板当即梦首帧。若用户另给旧宫格且要求拆格，应先核对实际边界与每格归属，作为另外明确的素材整理任务处理。

## 本轮验证边界

新增脚本行为通过真实排版与文件检查验证：中文断行/省略、说明行对齐、图片区域完整、计划与源帧哈希、修改计划不回写旧清单、已有文件/输入保护。合成色块仅作回归图；没有生成或验证真实花木关键帧、视频、账户模式与平台审核结果。具体测试数量及案例记录于 [验收案例](../evaluation/CASES.md)。
