# Amazon Plant Image Strategy

Help the seller discover what buyers need to understand before purchasing, then turn supported product facts and market evidence into a coherent image campaign. Deliver strategy and prompts; the user copies the prompts and uploads the mapped references into Lovart. Do not generate images, operate Lovart, publish listings, or assume paid research access as part of this skill.

## Project mode

Route from the user's actual input and request. Use `campaignMode: new-set` for a first campaign from product materials. Use `campaignMode: set-refresh` when the user supplies already designed old images and asks to update their layout/styling toward competitors; read [old-set refresh](references/set-refresh.md) before intake or source selection. The refresh mode preserves the resolved old-set asset scope by default and overrides new-set count/role assumptions below. Both modes retain competitor and review research, product truth and independent prompt handoff.

For set-refresh, default to rebuilding the old campaign design: reuse only supported product material and retained facts, then reconsider layout, copy, setting, palette and applicable camera choices. Preserve explicitly locked requirements, not incidental choices visible in the old artwork. Use `bounded-edit` only for a specifically limited revision or an explicitly retained design. After showing real reference candidates, let the user choose `designTransferMode: reference-replace` (retain the selected competitor's full composition, scene, typography combination and light) or `structure-adapt` (retain its layout structure while redesigning styling). Record scope and per-asset exceptions using [reference fidelity](references/reference-fidelity.md). Rebuilding our old design and faithfully inheriting a new competitor are compatible decisions.

Within reference-derived work, including `reference-replace`, allow bounded styling freedom by default: recolor optional styling vessels to separate the real product from its surroundings, modestly adjust camera angle/position to show supported product features, and add a few subordinate decorations or replace reference props with similar objects. Keep the source's recognizable layout, setting relationships, hierarchy and lighting character. Resolve concrete changes before writing the prompt, using [bounded styling freedom](references/reference-fidelity.md#有限生图自由度), rather than asking the generator to improvise. No per-change confirmation is needed within this scope; explicit exact-retention requests and identity-locked included vessels still take precedence. Missing product views remain evidence gaps.

## Defaults and scope

- Marketplace: Amazon US. Conversation and strategy: Chinese. Customer-facing image copy and Lovart prompts: English. Explicit project choices override these defaults.
- Lifestyle setting: recognizable US/European residential architecture and household styling, localized to the marketplace; default US projects to plausible American homes. Describe the architecture positively and avoid unrequested Asian/African themed decor. This is a setting preference, not a restriction on people or ethnicities. Explicit regional, cultural or product-use directions override it.
- Ask the user to state what the product is, upload original product materials (measurements, real photos, white-background and multi-angle details as available), and supply **3–6 unique competitor ASINs or links**. For new-set work, do not require finished secondary or A+ inputs. For set-refresh work, accept the uploaded finished images and request only missing identity/detail evidence needed by the proposed changes. Inspect existing uploads before requesting missing essentials.
- For **new-set**, deliver exactly **11 image plans and prompts: DIM01, DETAIL01, SCENE01–SCENE04, APLUS01–APLUS05**. In new-set mode, the six listing images are secondary images; no new MAIN is included. Set-refresh uses the recorded targetAssetIds; an existing main image is included only when within that refresh scope. Five A+ images means five image assets, not five arbitrarily expanding modules. Explicit later changes override this default.
- Production canvases: **DIM01/DETAIL01 default to 1600×1600 px; SCENE01–04 stay 1:1, with a per-image popup offering 1600×1600, 2000×2000 or 2048×2048; desktop A+ defaults to 1464×600 px**. Before final scene prompts, ask both the four types' allocation within the current SCENE scope (four assets for new-set) and each asset's square pixel size using [scene-type popups](references/scene-types.md). Prior answers or explicit scoped delegation skip repeats. Scene-style A+ retains A+ canvas rules. Keep production targets separate from verified account-slot acceptance.
- Research competitors in isolated browser tabs/sessions using [browser research](references/browser-research.md). When the optional `amazon-variant-gallery-scraper` skill is installed, discover its actual path and read [competitor collection](references/competitor-collection.md) first. Read its current concurrency/locking contract; gallery and A+ capture supports module provenance where available, while reviews require separate research. A direct-fetch failure begins recovery. After bounded recovery, use bundled historical sets for layout dialogue while preserving genuine research gaps; the scraper and an author's local disk are not prerequisites for using this skill.
- Exhaust the applicable browser and public-search recovery routes before requesting the smallest missing export. Continue unaffected work and allow a clearly incomplete draft. Never turn missing data into zero demand, positive findings, or invented metrics.
- Default to one saleable SKU/variant, but support explicitly requested multi-color/multi-product arrangements within the same 11-asset budget. Several uploaded colors do not establish a mixed sale unit or a placement rule. Follow [arrangement composition](references/arrangement-composition.md): map each source to its actual product/color and sale role, then use popups for any uncertain container count, single-type versus mixed contents, per-container allocation or pack implication. Distinguish live, artificial, dried, and preserved products; do not silently treat them as interchangeable.
- This skill is self-contained. The separate `lovart-plant-product-images` skill can execute individual image tasks when separately requested; it is not a dependency.

## Start with a conversation

Before selecting or adapting any template, apply the [missing-product-evidence gate](references/product-truth-compliance.md#缺失事实与可见细节门槛). Ask necessary factual questions directly in a popup; request actual uploads in chat. Dimensions, material composition, part structure, texture, finish, quantity and functional states must not be guessed from category norms, competitors, templates or generated pictures. A confirmed material name does not supply an unseen microscopic texture. Pause only dependent assets, and keep unknowns out of executable prompts; delegated design choices never confirm product facts.

Read [discovery](references/discovery.md). Default to frequent, iterative popup dialogue to understand the user's intent; do not minimize the number of rounds at the expense of clarity. Inspect supplied materials, then ask about ambiguous image roles, SKU identity, measurement targets and endpoints as soon as they affect a decision. Use the current mode's available text-input popup tool, with two or three concrete options when useful and free-text questions for unknown facts; never recommend a guessed measurement as a fact. After competitor visual research, discuss concrete layouts for every asset through [set layout dialogue](references/set-layout-dialogue.md), including follow-up choices about framing, detail windows, text, dimensions, backgrounds and lighting. Show reference images/links in chat before the popup when useful. If no popup tool is available, ask in chat. Wait for unresolved answers; do not submit the preselected option on the user's behalf. Request uploads in chat, not a text-only popup.

When the user has already requested competitor-based old-set refresh, record `competitor-derived` as selected and only clarify an unresolved principal competitor/set. Otherwise, after actually reading an ordered competitor set, use the [reference-route popup](references/set-layout-dialogue.md#先弹窗选择提示词参考路线): derive prompts from the just-observed competitor set, adapt built-in set prompts, or deliberately combine named sources. Show the real sets and coverage first; downloads alone do not count as reading. Do not silently select the built-in library after successful competitor research. Record the choice before finalizing dependent layouts; an explicit prior selection or delegation need not be asked again. This chooses a planning source, not a generation tool or permission to generate images.

Before writing final copy or its related prompts, read [copy and typography](references/copy-typography.md). Ask for basic Chinese/English copy in a text popup: supplied copy receives meaning-preserving English grammar/style polish; an explicitly submitted blank, skip or AI-generation choice delegates creation from supported facts. Offer a starter font menu including AI choice, Apple-style modern sans, basic sans, classic serif and restrained display/handwriting. Explicitly skipping font selection delegates it to AI; an unanswered popup is never a blank submission. Record scope, original input, final copy and font choice per asset. User-selected typography overrides creative defaults; no-copy/native-only routes stay explicit.

For visible copy, apply the three editing passes in that reference: preserve meaning and factual qualifiers, improve natural English, then fit the asset's message and space. Use [text layouts](references/text-layouts.md) to choose a compatible text arrangement and define each exact string, semantic line break, bounded text zone, type size/weight, alignment and emphasis. Keep sale-content limits readable. Resolve overflow during planning rather than asking the generator to rewrite copy. Ordinary grammar edits need no extra approval; changed meanings or locked phrases require focused clarification. Record design checks separately from actual rendered-text verification.

Persist the developing brief in `discovery.md`: confirmed facts and decisions, inferred ideas, unanswered questions, contradictions, and current stage. On resume, read it and continue from the open decision. New evidence can revise strategy; record affected assets instead of restarting the interview.

For loose stems and flowers placed into containers, total length alone is insufficient. Clarify the decorative body's endpoints/length, bare stem below it, trimming permission and actual support/insertion geometry when they affect the proposed image. Do not treat a 17-inch stem as a 17-inch flower head or hide surplus stem inside a short vessel. Multiple products/colors require an explicit source-to-container contents map; ask about unresolved combinations before finalizing dependent prompts, while continuing unaffected research.

Collect and research while maintaining a live dialogue. Use short popup batches as many times as needed: clarify materials and facts, compare layouts, refine each asset, then draft the confirmed direction. Each answer should inform the next useful question. Skip choices already answered or explicitly delegated; an overall style choice does not delegate all individual layouts, copy, scene allocation or pixel sizes. A user request for immediate output permits reasoned design assumptions, never invented product facts. Do not re-ask the fixed output count or SCENE 1:1 ratio; ask unresolved type allocation and per-scene square pixels as required above.

## Establish evidence before claims

Read [research and evidence](references/research-evidence.md) and [browser research](references/browser-research.md). Inventory photos by filename and role, inspect relevant images, and construct separate source, product, competitor-visual, review, keyword, intent, and risk records. For every ASIN, inspect its gallery, A+ visuals, customer photos and review text as accessible; record each section's actual coverage. Every customer-facing factual claim and factual visual implication must trace to evidence covering this SKU and this claim. Evidence IDs are internal metadata, not image text.

Execute research in passes: verify every competitor first, inventory gallery/A+ sections second, inspect accessible static images and sample available review text third, then compare and transfer findings. Read embedded product-detail-page reviews before trying the full review list; track these routes separately and preserve readable originals when the list requires sign-in or fails. The review budget is a ceiling, not a minimum. Preserve each competitor's ordered gallery and A+ narrative, common design rules and layout changes across the set; a thumbnail grid is an entry point, not a substitute for inspecting full images. Save each ASIN checkpoint after a section, so one slow page does not block the entire batch. Follow the coverage and recovery stopping criteria in browser research. Use [research records](references/research-records.md) and the bundled offline audit helper when Python is available; it normalizes inputs and audits supplied evidence records, but does not browse or prove observations itself.

Keep three distinct concepts: a source's reliability, what it actually proves, and how confidently a strategic inference follows. Competitor reviews prove sampled buyer concerns, not our product's performance. SQP and tool estimates do not automatically prove a competitor's organic visits. A risk score never authorizes an unsupported or prohibited claim.

For thin data, offer useful conservative concepts while labeling evidence limits. Preserve all scoped assets in the draft (11 for new-set); assets lacking indispensable identity or required product measurements remain `BLOCKED`, with conditional prompts clearly outside the ready-to-copy set. Unknown A+ account settings alone do not block default-canvas planning; mark upload review pending. Record competitor access failures per section, not as a blanket failure when other sections are readable.

## General visual structure analysis

For reference-derived work, use [visual structure analysis](references/complex-layout-analysis.md) to translate observed elements and relationships into executable prompts. Match analysis depth to the image: identify roles, region ownership, geometry, alignment, layers, visual hierarchy, spatial support, lighting and typography as applicable. Determine what makes the source effective, then specify retained relationships, product/copy replacements and necessary adaptations. Do not assume a scene count, dividing shape, palette or text treatment. Inspect uncertain details in context and map each important design decision to a concrete instruction and actual reference input.

## Scene, product and container fit

Before selecting a lifestyle setting or optional vessel, read [joint scene/product/container fit](references/scene-product-container-fit.md). Resolve the target-market architecture through the visible distance, including openings and reflections; default outdoor settings to plausible low-rise residential gardens, porches and terraces, not unspecified city skylines. Compare product–setting, vessel–setting and product–vessel relationships. Physical capacity alone does not establish balanced proportions or styling. Preserve included/fixed containers; automatically select unspecified optional props by actual silhouette, opening, depth, visual weight and use location. Ask about key conflicts or missing identity/facts, not every vessel choice, unless the user requests per-image selection. Apply these decisions to each scene/panel and its final prompt. Adapt incompatible reference props/backgrounds minimally; clarify conflicts with explicit user choices rather than silently overriding them.

Check functional vessel type before geometry or styling. Default to conventional flower vessels, plant pots or the product's supported base/hanging method. Do not use teapots, coffee pots, mugs, drinking glasses or wine bottles as flower containers unless the user explicitly specifies that use; replace these in competitor scenes with compatible conventional vessels. Their presence as ordinary background props does not authorize inserting the merchandise into them. Included/fixed containers remain identity-locked; clarify an actual conflict rather than silently replacing them.

## Text restraint and faithful reference adaptation

Before copy collection, ask in a popup for EACH asset whether it needs visible copy. Include its ID, task and recommendation; offer no text, minimal text, or information labels. Batch separately labeled questions when helpful. Record an actual answer per asset; a general style choice or permission to draft copy does not answer this question. Reuse explicit prior per-asset answers; no popup tool means ask the same question in chat. Then assign the confirmed copy mode: `none`, `minimal`, `informational`, or `native-only`. Read [text layouts](references/text-layouts.md) for the campaign-wide balance. Propose clean, no-copy images when the visual already communicates the task; do not manufacture a headline for every asset. Necessary dimensions and sale-content qualifiers remain readable. Only after no-copy is confirmed, skip copy-writing and font questions for that asset.

Text does not require a panel. For autonomous styling, default to no added backplate; use natural-background lettering, a local feathered white/light veil, or a designed panel when the image benefits. Keep colored panels on a minority of autonomously designed scenes. In `reference-replace`, retain the selected source's actual panels, text zones and type combinations instead of imposing these defaults or a panel quota. Feathered veils are allowed, including white, with smoothly fading edges and their full effect outside the product protection area. A different panel color on each image does not solve repetitive layouts.

For competitor-derived work, use [reference fidelity](references/reference-fidelity.md) to preserve the selected image's successful composition, setting, props, camera, light, information hierarchy and whitespace. A close adaptation may replace the competitor product with ours and change only palette/copy plus necessary product-fit corrections. Apply this to dimensions, details and A+ as well as scenes. Supply the actual selected reference image alongside our product references; name the retained features and exact changes in each independent prompt. Do not redesign a successful source into the same generic text-panel template.

## Write and deliver

Optimize prompts for image quality and controllability, not minimum length. Preserve all applicable product, reference-layout, scale, lighting, material, text and compositing instructions; expand them when the image needs precision. Remove redundancy only when no visual decision or necessary constraint is lost. Use the quality coverage check in [Lovart prompts](references/lovart-prompts.md) before handoff. Static checks establish instruction completeness, not proven generation quality.

Read [deliverables](references/deliverables.md) and [Lovart prompts](references/lovart-prompts.md). Write to a project output folder such as `outputs/<product-slug>/`, keeping source uploads intact:

- `design-strategy.md`: primary Chinese technical/design document, with competitor/review findings, cross-competitor comparisons, coverage, evidence, the target asset map and one brief per scoped asset (11 for new-set). Set-refresh includes the old-set diagnosis and links `set-refresh-map.md`.
- `competitors/<ASIN>.md`: individual research findings and observed visual records, merged into design-strategy rather than replacing its substantive analysis.
- `competitors/<ASIN>.json`: structured checkpoint for coverage, visual evidence, review sampling and recovery attempts; `research-audit.md` summarizes consistency errors and genuine remaining gaps. For multiple marketplaces, use separate project research folders.
- `evidence-ledger.md`: source locators, factual support, observations, sampling limits, contradictions, and risks.
- `discovery.md`: resumable decisions and unanswered questions.
- `layout-decisions.md`: full-set source comparison and the scoped assets' concrete layout choices, user answers/delegation, copy input/polish/final text, font selection, scene-type allocation, per-scene 1:1 pixel choice and panel/step/comparison details, common style rules and adaptations.
- `prompt-index.md`: readiness, required reference files, A+ slot mapping, and links to every prompt.
- `prompts/<ASSET_ID>.txt`: one self-contained English prompt per actual image; conditional drafts go in `prompts/blocked/` and explain the missing requirement.
- `prompt-manifest.json`: campaignMode, targetAssetIds for set-refresh, and the corresponding assets' status, file, ordered reference filenames/roles and conditions. New-set retains the fixed 11 IDs.
- `all-prompts.md` and `all-prompts.txt`: copyable prompt collections, one complete prompt per labeled asset; upload references before copying each prompt. Include executable READY/PROVISIONAL prompts with their conditions; list BLOCKED gaps separately without mixing conditional bodies into executable text. Compile from the individual files using `scripts/build_prompt_summary.py`, or preserve the same exact-text invariant manually when Python is unavailable. Do not create a PDF or a controller that asks Lovart to infer the scoped layouts. These are extra file views of the same scoped prompts, not extra image assets.

Every ready prompt must be independently usable: include its relevant identity/style constraints once, exact approved copy, reference role mapping, selected LAYOUT BLUEPRINT, and output specification. Translate the chosen source's information structure into explicit zones, window count/shape, typography, dimension lines and reading order while preserving shared campaign rules. Do not rely on another prompt, an internal evidence ID, a local path Lovart cannot access, or unstated conversation history.
