# 实物尺度、透视比例与主视觉校验

适用于花卉、盆栽、树木、花环及其他支持的植物商品。每张带场景/参照物的图在定版式前读取；尺寸图以真实测量端点为准，细节裁切不能被当作整件大小。以下是摄影与构图计算，不是平台占比规定。

## 尺寸对象与视图先绑定

DIM01的每条尺寸在Brief中绑定：测量对象/部位 → 原始数值与单位/事实来源 → 起止端点与整理状态 → 成图的具体全貌或局部视图 → 支持该视图的素材。整体尺寸只连到完整商品视图的对应端点；局部窗口仅在有独立实测依据且端点完整可见时标该部位尺寸。不从特写的像素大小、上传顺序或完整商品数值反推局部尺寸。

看不出素材是全貌还是局部、含盆与否或测量端点时，先向用户弹框澄清；缺完整视图时请求补图，不拿局部补画整件后标整体尺寸。等待期间继续其他资产。确认后在每条受影响prompt重复附件角色与尺寸绑定，不能只留在内部证据表。

## 散枝入载体分段计算

适用于散枝干花、仿真花枝等放入容器、且穗/花/叶主体应在口沿以上完整显示的情形。活体盆栽、盆中已有固定支架或多分叉弯曲花材按真实支撑结构记录，不强套直杆公式，不为容纳而剪根或改变随货盆。

### 先确认分段端点

- `L`：未剪整枝总长，切口底端到穗/花/叶最高尖端，记录直立/沿茎测量状态及依据。
- `B`：装饰主体沿**同一轴**的长度，从主体最低起点到最高尖端；不能把主穗长度、单朵直径、整束花冠高度混为一谈。用户只说“主体5英寸”且归属不明时，直接弹框问是单穗还是整束主体包络。错落花束的各穗长度与整束主体包络分别保留，不强行把所有穗排齐。
- `S`：主体下方裸茎长度；只有这两段确实连续且共用上述端点时，`S = L - B`。分枝/弯曲/错落结构可另记关键节点，不用未经标定的特写倒算长度。
- `C`：本图从下部裸茎剪去的长度，未剪为0。能力有SKU证据且采用剪裁已确认/委托才可非0；`0 ≤ C ≤ S`，不剪主体、不悄悄缩短全部素材。原长与剪后 `L-C` 分开标注。
- 载体外高 `H`、口沿到**实际支撑点**的有效竖直内深 `D`、口部容纳宽度/内壁限制、实际接触关系及各自依据。厚底、假底、填料或支撑会减小有效内深，不能把外高当成可隐藏全部茎秆的长度。未证实的内部结构不得作为商品特征画出。

读完已有测量与原图再问最小缺项。主体/裸茎分段影响当前图且未知时，先弹框确认数值与端点；缺测量图则在聊天请求。只知总长时可以继续无载体全貌尺寸图，不能宣称入瓶主体比例已核准；受影响容器图等待关键事实。设计道具的外高/内深可以明确选择并标 `design_assumption`；商品本体尺寸不能作设计假设。

### 插入改变遮挡，不改变产品分段

对直杆、主体完整在口沿上方、茎底实际落在支撑点的简化模型，令 `θ` 为茎轴偏离竖直的角度：

```text
剩余总长          = L - C
剩余下部裸茎      = S - C
插入轴向长度 I    = D / cos(θ)
露出裸茎轴向长度  = S - C - I       （不得为负，除非实际图允许主体被遮，改用人工模型）
口沿以上总高      = (L - C - I) × cos(θ)
露出裸茎竖直高度  = (S - C - I) × cos(θ)
主体竖直投影高度  = B × cos(θ)
台面至穗尖总高    = H + (L - C - I) × cos(θ)
茎底支撑点高度    = H - D
```

逐项检查 `0 < D ≤ H`、插入段未超过剩余裸茎、切口没有穿底/凭空悬浮。倾斜时还要检查茎轴穿过瓶口、内壁横向余量与重心稳定；公式成立不代表细口容器一定装得下。弯曲、明显透视/错落或不共面的组合使用来源支持的几何/关键节点，保留不能直接比较的局限，不捏造角度或焦距给结果兜底。

矮瓶的未剪花材通常露出更长裸茎；若不接受长露茎，优先换兼容的稳定容器，或在剪裁有依据且被选定时明确剪裁状态。不得通过穗头增大、裸茎压缩、藏茎穿底或换小家具修补。数值例集中见下方跨场景对照表，不从历史示例继承当前SKU尺寸。

### 先分段、再画幅

容器为主要竖直参照且近同深度时，分别算“完整摆放总高/外高”“主体竖直高度/外高”“口沿以上裸茎竖直高度/外高”，再由容器占画高推导三个画幅占比。至少在Brief与prompt约束：容器底、口沿、主体起点、穗尖这四个位置及相互间距；不能只有一个总高比。混放产品按每个产品–载体配对分别算，最长者决定整体上界，各产品主体长度保持自身比例。多个载体位于不同深度时分别处理投影。

透明载体还需可见茎底/茎轴连续、折射适度且支撑可信；不透明载体的遮挡不能豁免内部长度守恒。主体从哪里开始必须保持源图特征，不能把裸茎误生长为绒毛/叶片来遮比例问题。主体局部放大窗不参与此整件比例计算。

## 跨场景换容器的对照核算

先分清未剪整枝长L、单穗/主体长度B、口沿以上高度和台面到尖端总高，不能把它们统称“展示长度”。同一未剪SKU保持L/B和对应节点关系；随镜头变化的像素高度不属于产品变长/变短证据。逐图、逐容器或拼版格位记录H、D、C、倾斜/支撑依据，并列以下结果：

- 口沿以上总高 = (L−C)cosθ−D；露出裸茎竖直高 = (S−C)cosθ−D。
- 主体竖直高 = Bcosθ；主体/瓶高 = Bcosθ/H；露茎/瓶高同样分开核算。
- 台面至尖端总高T = H−D+(L−C)cosθ；容器底至口沿、主体起点和尖端分别定位。

对同一未剪枝条和相同倾斜状态，D减小多少，口沿以上高就增加多少。若H和D同步减小而H−D（支撑点距台面高）不变，T可以保持相同。这是正常几何，不能为制造不同“总高”把商品缩放。真正要排除的是深浅不同却无解释地保持相同口沿以上露出段、主体/瓶高比例也不变，或短瓶中隐藏超过D的茎秆。

以下为明确的合成算术案例，不是未来SKU或道具默认规格。设同轴直立单枝L=43.18 cm、B=7.62 cm、S=35.56 cm，支撑点距台面均2 cm：

|道具状态|H / D cm|C cm|露出裸茎 cm|口沿以上总高 cm|台面至尖端T cm|主体/瓶高|
|---|---|---|---|---|---|---|
|较高瓶、未剪|24 / 22|0|13.56|21.18|45.18|0.3175|
|较矮瓶、未剪|12 / 10|0|25.56|33.18|45.18|0.6350|
|较矮瓶、剪去12 cm，仅限已支持且选定剪裁|12 / 10|12|13.56|21.18|33.18|0.6350|

前两行整体摆放总高相同，但矮瓶上方露茎长12 cm，主体相对瓶高占比翻倍；不能将高瓶图的露出花材原尺寸原位置贴到矮瓶口沿。第三行若希望恢复相同露出长度，必须保留12 cm剪裁决定及剪后整枝31.18 cm状态，不把原长43.18 cm标到剪后结果。单穗模型不等于整束错落包络，整束仍按实拍关键节点保留高低变化，不强齐花头。

**英文prompt执行粒度（仅对应上述合成高瓶案例）**：

```text
Styling vessel: matte ceramic cylinder, external height 24 cm, usable vertical
depth 22 cm; these vessel dimensions are design assumptions. For the upright
representative stem, preserve the verified 43.18 cm untrimmed length, 7.62 cm
single plume and 35.56 cm lower bare stem. Rest its cut end at the stated support
2 cm above the tabletop. Insert 22 cm: leave 13.56 cm of bare stem plus the
7.62 cm plume above the rim, giving 21.18 cm rim-to-tip and 45.18 cm tabletop-to-tip.
The single plume height is 0.3175 times the vase height. Preserve the photographed
staggered bouquet envelope separately; do not align every head to this stem.
```

在矮瓶图须把本段整体换成该图H/D、插入、露茎和比值，不能只把“ceramic cylinder”改成“short vase”而照抄所有数字。最终prompt不能只说“proportionate vase / realistic 17-inch stems”代替已选定的分段结果。

跨图不能直接比较未经标定的商品像素高度。先在每张图的同深度可比轴上核验瓶高、露茎、主体和整体摆放比例，再比较相同实物状态。变化可由已记录的剪裁、真实支撑、倾斜或相机投影解释；不任意改角度或编造隐藏支撑强行凑比例。更换透明/不透明容器时同样核算，遮挡不免除长度守恒。算术核对只证明计划自洽，成图仍需查看瓶口、茎底/支撑、主体起点和尖端；端点不可见则标未能核验，不能仅凭文字“17英寸”验收。

## 三个数必须分开

1. **商品实物尺寸**：适用SKU、宽/高/深、含盆与否、整理状态、来源P。只给外沿宽度时不能顺手假设高度也相等。保持源图可信宽高关系，不能用独立拉宽/拉高塞进版式。
2. **商品对参照物的比例**：选明确端点与同向轴，如整件高度对同平面柜高、花材外宽对同深度桌宽、挂件外沿对完整门板宽。参考值分实测、用户确认、设计假设；“常见家具”不是该场景已测量的事实。
3. **商品画幅占比**：商品投影宽/高相对图片宽/高，用于取景。它由相机、空间和真实比例一起决定，不能写成第二个互相冲突的商品放大指令。

同款跨图固定的是实物尺寸与支持状态，不是相同像素占比。中远景可以较小，近景可以较大；不得通过缩门、矮桌、巨型茶杯或改小沙发维持商品占比。

## 每张图的尺度记录

|字段|最少需要记录的内容|
|---|---|
|Product|P来源、测量轴/端点、实物值与状态、轮廓宽高关系|
|Stem segments（适用时）|总长/主体/下部裸茎、端点和依据，原长/剪后状态；单穗与整束主体包络分开|
|Container fit（适用时）|每载体外高/有效内深/口部容纳依据，插入/露茎/主体投影、支撑与剪裁决定；逐配对检查|
|Primary anchor|一个主要参照物、完整测量端点、尺寸值、实测/确认/设计假设|
|Plane / axis|相对镜头深度、是否同平面近似、轴是否可比/被透视压缩|
|Ratio|实物比、投影比或保守范围、计算方式与未知因素|
|Framing|主要参照物画幅占比，据此推导商品占比、位置与裁切限制|
|Secondary check|有用时用另一尺度线索复核；不强制每张塞满两个道具|
|Support / clearance|盆底/台面/地板/挂点关系、开合/通行/容纳余量|
|Verification|规划计算结果；出图后是否真的看到可比端点、实际目视/像素估计及局限|

门板比较需看门板左右边，不用窄的镶板内框冒充门宽。已锁定的商品容器或本图设计道具不在生成阶段擅自换规格；设计阶段允许选择不同场景道具，并按上方跨场景核算重新计算。地面树的总高不能与远处近天花板的装饰物直接作无透视换算；杯子、蜡烛、书本尺寸变化大，只宜作辅助，除非实际规格已知。

## 先算比例，再定镜头与文字区

同深度、轴近似平行像平面时：

`商品/参照物投影比 ≈ 商品实物尺寸 / 参照物实物尺寸`

`商品画幅占比 ≈ 该投影比 × 参照物画幅占比`

如果一份设计写30cm宽花材对60cm宽同深度搁板，同时搁板占画宽80%，则商品约占40%画宽；不能又命令商品占70%。要更突出商品，可收紧镜头让参照物部分出框、减少道具或改变布局；说明取景变化，不能改变实物比。若此图需要完整参照物，又无法同时满足文字区与真实尺度，就改文字位置/分区或机位。

不同深度时，在透视近似和可比轴条件下：

`投影比 ≈ 实物比 × (参照物距相机 / 商品距相机) × 轴向投影修正`

镜头前方茶杯自然显大，不可拿其像素大小直接判断后景花盆尺寸。强斜视门面需同平面透视还原/可解释的构图估计；无足够几何资料就记“不可直接像素比较”，换近同平面的参照或更正面机位。不得从单张无标定图编造焦距/距离来让公式成立。辅助道具与商品深度不同，不能强制二者遵循同平面比例。

每张优先给**一个自洽的尺度目标**，再推取景；不要同时给很多独立且矛盾的百分比。给布局区间时它是容纳区域，商品在区内等比拟合，不是强制变形的宽高框。远景商品不够辨认时，先减背景竞争/缩短观看距离，不增密、不增大实物。

## 主视觉优先级，而非强制画面几何居中

商品可以偏左/右给文案留位，但应是第一视觉对象。检查商品清晰度、局部明暗/颜色分离、完整可辨轮廓，与前景道具/灯火/画作/文字的竞争。大面积深色近景、正脸人物、强亮灯点、高对比画作、相似且更茂盛的植物都可能夺焦；按当前图减少、缩小、降对比、后移或柔化**道具/背景**。不靠模糊商品、削弱枝梢或夸大尺寸提升主次。

“商品主视觉中心”指视觉关注优先，不要求每张都摆正中，也不要求所有场景固定相同占比。实际有用的小物可以保留，位置与作用见[场景拓展](scene-expansion.md)。

## 可选算术助手与边界

Python可用时，用 `scripts/scale_check.py` 校验已经选定的尺度记录；否则在brief手工给同样算式。程序不读图、不识别物件、不核实参照尺寸，不会把场景自动校准。输入只接受统一cm值，单位换算先另行核对。可比轴/深度关系由设计者负责。

助手的画幅占比输入针对可见完整参照物/完整商品，范围(0,1]。参照出框的近景可另选完整可比标尺或保留人工透视判断，不能把残留的可见宽度当完整实物宽度。

示例为合成设计输入，不是待填占位模板：

```json
{"assets":[{"asset_id":"SCENE01","product_cm":30,"reference_cm":60,"reference_basis":"design_assumption","projection_mode":"coplanar_parallel","reference_frame_fraction":0.8,"product_frame_fraction":0.4,"relative_tolerance":0.1}]}
```

```text
python scripts/scale_check.py --input project/scale-plan.json --output project/scale-audit.json
```

- `reference_basis` 为 `measured` / `user_confirmed` / `design_assumption`，假设始终显示警告，不包装为实测。
- `projection_mode` 为 `coplanar_parallel` / `explicit_factor` / `unresolved`。`explicit_factor`另给正数`perspective_factor`，说明其来源；未知透视选unresolved，程序不判断投影比是否合格。
- 可选`observed_product_px`与`observed_reference_px`必须成对，是人工确认可比端点后录入的像素估计，不是自动识别。`relative_tolerance`默认10%仅作诊断阈值，可按证据与误差修改，不是产品公差或平台容许失真。
- 输出能发现算术/规划比例矛盾或已录入观察的大幅偏差。没有观察值时`visual_check`为not_provided；输入一致、退出码0不代表成图保真。unresolved仍需人工处理，不能写通过。

### 散枝与多个载体的助手输入

散枝模型使用可选 `stem_geometry`。`total_cm`、`body_cm` 和各自 `total_basis` / `body_basis` 必须为已实测或用户确认的同轴值（`measured` / `user_confirmed`）。`bare_cm` 可额外录入，若与总长减主体矛盾则报错。载体给 `container_height_cm`、`usable_depth_cm`、`container_basis`（可为 `design_assumption`）、`tilt_degrees`（不填为0）及 `trim_cm`（不填为0）。非0剪裁须给有证据的 `trim_allowed: true` 与选择状态 `trim_decision: confirmed | delegated`。这些录入不是程序自行证明事实。

模型推导 `product_cm` 为台面到穗尖的完整摆放总高；可省略该冗余值，也可填入供交叉核对，不再用未剪整枝总长冒充插瓶总高。`reference_role: container` 时核对 `reference_cm` 与载体外高一致。其他参照仍须可比竖直轴。

```json
{"assets":[{"asset_id":"SCENE01","reference_role":"container","reference_cm":18,"reference_basis":"design_assumption","projection_mode":"coplanar_parallel","reference_frame_fraction":0.27,"product_frame_fraction":0.6627,"body_frame_fraction":0.1905,"exposed_bare_frame_fraction":0.2022,"stem_geometry":{"total_cm":43.18,"body_cm":12.7,"total_basis":"user_confirmed","body_basis":"user_confirmed","container_height_cm":18,"usable_depth_cm":17,"container_basis":"design_assumption","trim_cm":0,"tilt_degrees":0}}]}
```

可选 `body_frame_fraction` / `exposed_bare_frame_fraction` 分别核对主体、露茎画幅；有真实可比像素估计时可录入 `observed_body_px` / `observed_exposed_bare_px`，与 `observed_reference_px` 配套。主体像素不是整束错落穗头包络；脚本不识别端点。缺分段观察仍保留 `segment_visual_check: not_provided`，不因为整体比正确而宣布局部比例通过。

多产品/载体可用一个资产下的 `instances` 数组，每项含唯一 `instance_id`、`product_id`、`container_id`，以及一份上述完整尺度输入（不另设asset_id、不嵌套instances）。例如同一SCENE01的 `V01-blue`、`V01-white`、`V02-blue` 分别校验；资产仍只算一张图。程序不替代[内容表](arrangement-composition.md)的数量守恒、售卖身份、混放分配与弹框确认，也不检查瓶口/内壁/稳定性。

## 出图后反馈（仅用户另行授权生图/复核时）

在原分辨率看完整轮廓、参照端点、前后关系和局部支持，再看小屏主视觉。可比时核对观察投影比与设计；不可比时说明原因，不给假精确百分比。明显偏差只修该图的尺度/取景及其后果（挂接、接触影、投影），保留商品身份和已合格其他图。不能只在报告写“约61cm”便视为画面比例已校准。

容器花材额外逐项看穗/花/叶主体长度、裸茎长短、口沿遮挡/插入量、是否穿底或悬浮、是否偷剪；总高正确但主体被放大仍不合格。多个载体核对各自颜色/品类和数量分配，不用一瓶通过代替全图检查。
