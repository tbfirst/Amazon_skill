# 研究、证据与可追溯性

## 输入与取数

先整理用户实际给出的产品文档、图片、竞品 URL/ASIN、评论导出、关键词报表。为每个文件记录名称、版本/日期、所属 SKU 与用途。图片分为主体身份、多角度细节、尺寸实测、包装/到货状态、场景/风格参考；不同角度不代表不同件数。无法打开的图片不能写成已经目视确认。

在现有 `evidence-ledger.md` 建立素材角色表：稳定图源ID、真实文件名、画面识别特征、SKU/变体、完整商品/局部及部位、允许用途、禁止用途、识别或用户确认依据、未决歧义。一个文件内有多个视图时分别定位区域。角色不由上传先后或清晰度决定；不确定就按[素材澄清](discovery.md#素材歧义先澄清)弹框询问。局部特写不能提供整件轮廓或整体尺寸；测量资料只支持与其对象、端点及状态匹配的值。

ASIN 必须结合站点核对详情页标题、变体和在售对象。用户提供 3–6 个不同竞品时全部纳入并行研究，不擅自只分析其中 3 个；重复项去重。超出范围时先说明优先级，少于范围时分析已有项并请求补充。对活植/仿真、尺寸、含盆与不含盆、单株与套装分别比较。

使用实际可用的公开网页或用户已授权工具。记录访问日期与成功读取范围。网页工具读取失败后先执行 [浏览器恢复](browser-research.md)，实际检查页面、图库和 A+，不能直接停在“直链失败请导出”。合理恢复耗尽或遇到必须由用户处理的访问要求后，再说明精确缺口并请求最小资料。搜索摘要仅作线索，不能充当已读完整评论。没有数据工具时不声称已用 Helium 10、卖家精灵、SQP 或反 ASIN。

请求最小字段：

- 评论：ASIN/变体、评论 ID 或 URL、星级、日期、标题/正文，已有时保留 verified purchase、语言和 helpful votes。
- 关键词：词、站点、时间范围、来源工具、对应 ASIN、搜索量/排名/流量字段及其含义；不存在的列留空。
- 自家经营数据：用户愿意提供时记录曝光、点击、会话、订单或退货原因及口径；不需要为写策略强制索要账号。

## 证据账本

采用稳定 ID：`SRC` 来源、`P` 产品事实、`V` 竞品视觉观察、`R` 评论主题、`K` 关键词观测、`IC` 意图簇、`J` 购买任务、`C` 拟用主张、`X` 风险。V 的具体编号与记录见 browser-research。事实修订保留被替代记录；不要把旧 ID 重新用于不同内容。

每条原始证据至少记录：

| 字段 | 要求 |
| --- | --- |
| ID / Source_ID | 稳定编号及原始来源 |
| Source locator | 网页 URL，或文件名 + 页码/工作表/行号/图片区域，或用户确认所在轮次 |
| Observed / retrieved date | 数据时期与读取日期分开 |
| Scope | 我方或竞品 SKU/变体、站点、测试条件、时间范围 |
| Finding | 实际支持的事实/观点，不扩大结论 |
| Class / strength | 证据类型与强度分别记录 |
| Limitation / counter-evidence | 样本偏差、冲突、缺失条件 |
| Allowed use | 可用于哪条主张/哪张图；不可支持什么 |

证据强度仅为项目内工作标记：

- **A / 直接材料**：与主张范围匹配的测量、检测/认证、原始平台报表或清晰照片；照片只证明看得见的外观，平台报表只证明其口径内数据，A 不自动允许写 tested/certified。
- **B / 有来源陈述或观察**：用户确认、厂家规格、工具估计、竞品评论聚合。用户确认可以支持一般规格，但不会因此成为第三方认证；评论不能证明我方性能。
- **C / 推断或未核实**：潜在使用场景、语义需求猜测、无来源主张。可用于内部假设和提问，不以产品事实形式进入主视觉、FAQ、alt text 或提示词。

不采用“A 就写认证、B 就写兼容、C 塞进 FAQ”的自动转换。`designed to` 也不是免证据措辞。缺证据的宣称应删除、收窄到实际可见事实，或阻塞相应图。

## 评论主题分析

区分 1–3 星抱怨、4–5 星惊喜、改进请求、误购原因与 Q&A。以实际文本判断主题，不把星级当情绪结论，不把情绪分数当业务结论。

先按[评论采样步骤](browser-research.md#评论与买家图的采样步骤)读取商品详情页内嵌顶评，再按需补完整列表。列表受限不使已读原文失效；只有公开顶评时，以实际唯一原文数作 N，并标注默认排序、采样日期与来源偏差。不能把这类小样本的主题排序称为总体买家需求排名，也不因少于30条而报0。

去重评论 ID/重复正文；区分父子变体，标记无法确认的归属。同一条评论可有多个主题，但同一主题在该评论中最多计一次。每主题报告命中评论数 `n`、实际分析的唯一评论数 `N`、适用筛选条件和涉及 ASIN 数；如只拿到差评，比例的分母就是该差评样本。不要使用页面总评价数冒充已分析样本量。多标签主题比例之和可超过 100%，需说明。

每个 `R` 记录：主题、抱怨/请求/惊喜/误购、n/N、适用竞品与变体、短摘录或忠实转述及定位、反例、买家问题、可由图片解决的部分、仍属产品/运营问题的部分。Q&A 答案和平台 AI 摘要单列，不混入评论计数。不能读到原文时不编造引用或“Top3 高频”。

## 关键词与需求入口

明确区分：

1. **报表数据**：注明原始口径；SQP 的查询表现、品牌/ASIN点击份额等不能自动解释成竞品自然访问量。
2. **反 ASIN 工具估计**：注明工具、日期、站点、估计属性，分清自然排名、广告排名、流量估计。
3. **公开搜索观察**：搜索结果、自动补全、标题用语等可证明观察到的词或位置；受时间、地域、个性化和广告影响，不证明月搜索量或历史自然流量。
4. **语义推测**：由产品与买家任务产生的候选入口，显式标为待验证需求，不写成已排名词或竞品流量词。

用真实字段保留未知值 `unknown`，不以 0 代替。关键词先按意图聚类，通常 4–6 簇但不硬凑：精确购买、场景/问题、对比替代、尺寸/摆放、套装/礼品、品牌/信任。每簇保留代表词、来源类型、支持证据、对应 JTBD、可能误导的词和分配图片。

只有具有同站点、相近时间、同样深度的真实 SERP URL/ASIN 集合时，才用共享 URL/ASIN 重叠辅助聚类；没有这些数据就做语义聚类并说明。不要为使用算法编造 SERP 数据。

## 从证据到画面

每项主要设计建立链条：`SRC/P/R/K → IC → J → C → ASSET_ID`。

视觉设计另建立 `竞品图 V-ID → 观察到的布局/光影 → 迁移理由 → 我方构图建议 → ASSET_ID/prompt`。实际看到图才能写 V 观察；仅有 alt 文本不证明布局、色调、阴影。图像与文字有冲突时保留冲突，不让生成提示词替事实做裁决。

外部家居/节庆场景检索使用单列来源（如`SRC-INSP01`）：查询、URL、日期、正文/图片实际读取范围、发现的场所/时段/季节/道具、迁移与排除理由。它不是竞品V、产品P或买家R，不改变ASIN/评论覆盖数。通过P事实约束后，可把适配的空间假设写成原创背景设计，但不能写成已证实性能、广泛需求或全年适用宣称。场景检索流程见[scene expansion](scene-expansion.md)。

`R` 和 `K` 解释为什么值得回应这个问题，`P` 才能证明我们怎样回应。例：竞品有人抱怨“盆很小”，可引出我方盆口尺寸图；我方真实测量支持具体尺寸，但不能据此写“比所有竞品更大”。缺少评论/词表时保留需求假设与未测字段，策略结论降为 provisional。

风险登记：风险 ID、触发画面或措辞、可能误解、支持/反对证据、严重度、处理（删除/收窄/补资料）、受影响资产与状态。涉及身份或实测冲突时，先阻塞冲突项，不用平均值和美化图片解决。
