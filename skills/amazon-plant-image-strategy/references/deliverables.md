# 交付文档与单图 Brief

默认输出Markdown和UTF-8纯文本提示词，另交付 `all-prompts.md` 与 `all-prompts.txt` 两份总汇。不要自动制作PDF，尤其不要沿用历史 `lovart-handoff` 的PDF总册。用户明确要求其他格式时再按其要求处理。

## design-strategy.md 结构

1. **项目摘要**：产品/SKU、站点、目标、用户、主购买任务、核心主张、数据充分度、选定方向与日期。
2. **产品事实**：真实/仿真/其他类型、外观、规格与测量口径、材料、套装、随货与不含物、状态差异、身份锁、关键 P 编号。
3. **逐竞品研究与横向对比**：3–6 个去重 ASIN、请求/落地变体、每区访问状态、实际恢复路径；各竞品主图/副图/A+ 的视觉分析、评论图与卖家图落差、评论原文主题 n/N 与反例。每套保留有序图谱、跨图共同规则及版式变化节奏，不能只有代表图。展示布局、主体占比、文字层级、明暗、光向、阴影、背景、场景和优缺点的对照矩阵。区分原文、平台 AI 摘要与独立推断；缺口明确，不能只有一串外链。
4. **自然流量词 / 搜索需求入口**：真实流量/排名报表、工具估计、公开搜索观察和推测需求分别列出，保留来源、时期、口径和未知值。
5. **意图与 JTBD**：IC、代表词、证据、用户情境、所需结果、购买障碍、对应图；每个主要任务可追溯到用户确认或研究。
6. **风险与证据**：主张 C 到证据 P 的映射、竞争研究的启发、反证、禁用说法、数据/视觉缺口及处理。
7. **创意策略**：考虑过的方向、选择理由、优先级、产品身份锁、视觉锁、文案基调与制作规格。附竞品与LIB库候选对照、实际检索/阅读/目视范围、弹框回答或用户委托及11张版式摘要，链接layout-decisions。依[文案与字体](copy-typography.md)记录基础文案/润色稿/最终稿、字体菜单选择或AI委托、大中小层级及例外版式。依[四类场景](scene-types.md)记录4张的类型张数分配及逐图方图像素回答。附场所/时段/季节/活动候选表：产品适配、事实/竞品观察/外部启发/独立假设、空间限制、道具作用、入选或排除理由；附实际场景检索查询/URL/日期/已读范围与入选图的建筑、配色、文字/字效、光影矩阵。记录每张尺度计算与主次检查，不能仅列“真实比例”。
8. **11 张资产图谱**：DIM01、DETAIL01、SCENE01–04、APLUS01–05；各图任务、主要问题、意图、事实依据、竞品 V-ID 与迁移理由、顺序建议、状态。标明场景类型、1:1与所选像素，四类张数之和为4；说明各场景资产的任务差异和每张 A+ 的新增价值；不增加 MAIN。
9. **11 份单图 Brief**：每个固定资产独立一份，用下面的结构；不得合并四个场景或五张 A+，不得把竞品某图当作我方商品。
10. **A+ 原生字段交接**：模块名称、字段、英文内容、图槽/桌面/移动端映射、实际要求来源。纯文本模块同样记录，但无需伪造图像 prompt。
11. **实验与验收**：指标口径、基线来源、单变量假设、样本与观察期局限、回退版本、出图后检查。
12. **缺口与下一步**：阻塞资产、每项所需的具体信息；已可复制提示词入口。链接 evidence-ledger、discovery、prompt-index。

文档结构是最低内容要求，不要求机械输出空表。“没有数据”和“没有需求”不同。禁止填入虚构 ASIN、客户评论、搜索量、检测结果来完成模板。

逐竞品研究中附覆盖表：ASIN/变体、区段、状态、已观察数/盘点总数、计数单位、原文评论 N、来源、缺口及下一步。未知总数写 unknown，不计算伪精确覆盖率；A+ 模块数与图片数分开。链接 `competitors/<ASIN>.json` 检查点和 `research-audit.md`，并说明离线检查是否运行。JSON、单竞品 Markdown 与本技术文档应来自同一批观察；脚本通过仅表示记录内部一致。

## 单图 Brief 模板

以下为写作模板，交付时填成实际内容；无适用项注明不适用，未知项说明其影响。必须核实的值未知则不能把状态写为 READY。

```markdown
### ASSET_ID / 中文图名
Status: READY | PROVISIONAL | BLOCKED
Readiness scope: 提示词可执行 / 平台复核 / 成图验收分别说明
Placement: secondary dimension | secondary detail | secondary lifestyle | A+ image
Scene type: single | four-grid | installation | comparison；非场景资产不适用
Scene allocation: 本图在已确认4张分配表中的位置；场景型A+不占SCENE名额
Module_ID / module type / slot: A+ 必填；listing 不适用
Objective: CVR / 减少误购退货 / 型号选择 / 其他具体目标
Priority and rationale: 数据或定性依据，分数如使用则标口径
Target intent cluster: IC-ID、代表词、K-ID、来源类型
JTBD: J-ID；当…我想…以便…
User question answered: 一句主要问题
Single message: 本图唯一主信息

Message hierarchy:
- Copy decision: user-polish / ai-generate / no-copy / native-only；原文、锁定词、润色/生成稿、最终稿与回答/明确提交空白/委托依据；未答项pending
- Copy edit: 保义/自然英文/版面适配三遍结果，关键修改原因、保留条件/数量/单位及证据，跨图术语/大小写/语气一致与信息去重；不重复堆叠原文与备选口号
- H1: 最终英文文案；不需要图上文字时 NONE
- Proof line: 最终英文事实/适用条件；不需要则 NONE
- Supporting text: 一个必要补充；或 NONE
- Claim-to-evidence: 每条 C-ID → P-ID；R/K 说明任务来源
- Native module text: 仅 A+ 原生文字字段，不能误写进图片
- Font decision: 用户所选基础字族/自定义或AI选择、覆盖范围、单图统一font_lock及明确批准的混排例外、回答依据与状态；真实排版才记字体文件/许可

Visual composition:
- Reference route: competitor-derived/library-template/hybrid/original；路线选择/委托依据、主套图、图库/A+覆盖、本图源图映射
- Layout decision: confirmed/delegated/proposed、决定依据、来源V-ID/LIB-ID，链接layout-decisions
- Reference transfer: 实际主来源图片/附件、分区/主体/文字/底板/光影保留项、必要适配与依据、源图→方案→prompt对照及附件就绪状态；见[迁移约定](reference-fidelity.md)
- Scene styling: 逐场景/格位文字色与底板色、局部背景明暗及理由；容器身份、造型/材质、H/D/口部/底部和依据；跨图复用/变化及参考适配
- Quantity/density: 真实每包数量、本图展示分配、整包/部分、已确认密度实拍与不确定项；成图计数和疏密未验时明示
- LAYOUT BLUEPRINT: 已选骨架、分区顺序、全貌/特写窗数量和形状、阅读路线；与prompt逐项一致
- Scene structure: 四宫格逐格风格/地点/商品/标签/光影；安装图实际步骤/动作/依据；对比图变量/不变量/顺序/分割及事实边界；不适用项略
- 版式分区/线框、主体占比与位置、文字区/安全区（可用归一化百分比；建议值非实测）
- 镜头视角、景别、真实尺度参照、透视、景深和背景
- 生活场景适用：场所/节日与依据类型、目标市场、2–3个建筑锚点、前中后景；挂放支撑与安全距离；流程近景写操作面/动作，对比可保留同地点
- 商品对家具/门窗的实物比例与画面占比分列，不能互相替代
- 主要参照物完整端点/尺寸与依据、商品/参照轴向和前后深度、投影比例/限制、由此推导的自洽取景；见scale-and-composition
- 散枝适用：总长/主体/下部裸茎的端点、数值与依据；单穗与整束包络分开；载体外高/有效内深、支撑、插入量/露茎、主体和台面至尖端总高；剪裁能力与本图剪裁决定/原长和剪后尺寸；跨容器比较口沿以上高、露茎、主体/瓶高及台面至尖端总高，不要求总高机械不同
- 多色/多品类/多载体适用：逐载体内容表（产品/颜色、数量分配、附件来源、各自尺度）；同时陈列或替代用途；售卖关系和弹框回答/委托及未决项
- 背景主色/辅助色/点缀色的角色与建议比例；商品固有色单列
- 必需特写与来源照片；允许调整与禁止变化
- 文案区域、字族/字号层级/字重/行数/对齐/对比、移动端阅读与安全区域
- Text map: 采用TYPE-01–08或已有骨架的文字布局；每元素copy_id、exact_text、line_texts、明确坐标基准的zone、具体字体/字号目标/字重/行高/字距/对齐/字色及强调短语；NONE/原生字段分别处理，见text-layouts.md
- Text check: design-checked; render-unverified，或本次实际排版/成图检查的尺寸与问题；没有真实渲染不能声称已适配字宽或小屏验收
- 字号按大/中/小建立层级，卖点详略、字重和颜色按重要性变化；米白底区/细边框标签/手触细节若采用，记录用户选择、区域与事实依据
- 艺术字适用范围、准确标题、具体字形/笔画/行数/字色/文字容纳区与完整商品缓冲；用户字体选择优先，AI选择时适用短标题主动给展示字；无字/原生字段/朴素选择明确记录；模糊/渐变与所有字效不进入商品
- 道具清单、功能/位置/深度/视觉优先级与售卖范围区分；禁出现物
Lighting and shadow:
- 可解释的光源、相对相机的光向、光源高度/表观大小、亮面暗面、反差、补光目的与色温倾向
- 自身层次、接触影、商品投影、环境投影；受影平面、方向/长度/软硬、距离与影缘关系
- 新背景与原实拍背景/旧投影的处理；局部明暗与真实材质高光
Competitor-to-design rationale:
- V-ID / 竞品 ASIN / 图序或 A+ 区域 / 来源定位
- LIB-ID / 库版本与文件 / 实际阅读或目视范围（如采用库）
- 实际观察 / 我方设计建议 / 迁移理由 / 不沿用元素
- 未看见竞品图时明确写独立设计建议，不伪造图像依据
Reference mapping:
- 图源 ID、本张附件序号、真实文件名、画面特征、完整/局部及部位、允许使用区域与用途、禁止用途、识别/用户确认依据
- 每条尺寸的对象/部位、值与单位/事实来源、端点/状态、目标成图视图与支持素材；不适用时注明
Identity lock: 本图必须保留的产品属性与允许变动
Style lock: 配色、背景、光线、文字/标注风格；文字默认直接融入背景，单独色块/底条须写必要理由或用户选择；实际加载字体才记文件，纯prompt只记字形风格
Output: DIM/DETAIL默认1600×1600；SCENE固定1:1，逐图记录弹窗选定1600/2000/2048方图或明确覆盖；桌面A+默认1464×600/61:25，sRGB目标；另列实际槽位/上传状态与出图后实际像素
Compliance gate: secondary / A+ 适用检查及政策来源/日期
Risk & counter-evidence: X-ID、风险、删去/收窄/补证方式
Alt text / accessibility description: 最终英文自然句，注明目标字段是否存在
Success metric: 数据来源与口径；不能取得时说明
Test hypothesis: 单一变量、基线、观察/样本条件与回退点
Prompt file: 实际可点击路径，blocked 必须显式标记
Acceptance: 生成后可观察的检查点，不能提前写通过
Owner / Due / Revision: 已知值或未指定，不编造负责人与截止日期
```

## prompt-index.md

用一张表列所有实际图片：资产 ID、中文目的、场景类型（适用时）、READY/PROVISIONAL/BLOCKED、必需参考文件及上传顺序、像素/比例、A+ 槽位、提示词链接、剩余条件。另列纯原生 A+ 模块字段，不混入图片数量。

`READY` 仅表示提示词本身具备已知输入并且没有阻塞条件，不等于生成图已通过审核。`PROVISIONAL` 适用于保守可执行但市场依据薄弱、或用户明确授权自行选择测试画布/暂拟模块等情况，必须指出不确定性；测试可生成与正式账户可上传分列。如包含无法解析的占位尺寸、图片来源或产品事实，应为 `BLOCKED`。

默认恰好 11 个 brief 和 11 份 prompt：DIM01 ×1、DETAIL01 ×1、SCENE01–04 ×4、APLUS01–05 ×5；blocked 草案也计入总数并单独列明。未知资格/尺寸不擅自取消五张 A+ 策略，也不产生额外占位图。真实模块需要更多独立图槽/移动端派生图时，说明适配缺口，再由用户改变范围，不静默扩数。

默认画布已知时，不因账号模块未知把全部A+ prompt放入blocked。brief/index/TXT均填实际制作默认值或逐图选择值，上传适配待核单列。SCENE类型分配/像素弹窗未答且未委托时，其最终prompt不能因已有1600默认而提前就绪。若用算术助手，将实际选择的输入保存`scale-plan.json`，检查结果保存`scale-audit.json`；无Python则在brief保留手算与局限。外部灵感在现有证据账本记SRC-INSP，无须为每个查询创建额外报告。

## 完成检查

- 每个资产 ID 唯一，图谱、brief、index 和 prompt 一一对应；固定 1+1+4+5，没有 MAIN 或额外 A+ 图。
- 实读竞品套图后已弹窗选择参考路线，且具体ASIN/变体/套图也已选或有明确委托；逐图遵循选中主套图及辅助来源，未答不默认使用内置模板，下载与完整目视分开。
- 场所/节日候选有适配和排除理由；四类张数及SCENE映射已经弹窗确认或明确委托且合计4；各资产有新增任务，生活场景有可识别的本地住宅结构，安装图不被强加房间/节日，不为拓展节日改变固定商品配饰。
- 五张 A+ 有信息递进和版式节奏；参考图的数量/手机端不静默扩数，原生多图槽与组合位图分清。
- 文字不压商品关键特征；配色有主次角色而非统一模板。每图光源、亮暗面、投影与支撑平面一致，挂件不出现盆底落地影。
- 实物尺寸、参照物完整端点/依据、前后深度、投影比与取景自洽；跨图允许景别改变，不允许实物尺寸漂移。未观察成图不能标比例验收通过。
- 场景需要拓展时已执行公开检索或如实记工具限制；外部图不混入V/P/R，不为凑时段/季节改变商品。辅助道具不抢主视觉。
- 已弹窗收集基础文案与字体选择；有输入保留原意润色，实际提交空白/明确跳过才委托AI，未答/关闭/超时不算提交。最终文案无新增无依据性能，用户锁定词未被静默改写。
- 所选字体优先；AI选择时适用短标题采用具体艺术字/展示字。大小/字重/颜色有明确层级，事实/单位清楚，尊重无字/原生字段/朴素选择；默认单图全部文案同字族，以大小/字重/颜色分层；可按来源或设计委托采用非黑色字、黑底白字或其他协调填充框，逐项给出底板范围/内边距。每个字形、长笔画与字效均不遮完整商品或擦掉细枝；检查无字构图及加字后的主次。
- SCENE01–04固定1:1，逐图1600/2000/2048方图选择有实际回答或明确委托；DIM/DETAIL默认1600方图、A+桌面默认1464×600，明确后续覆盖另记。制作画布、真实账号槽位、实际返回像素分开记录。
- 四宫格每格为不同风格场景并含对应同款商品；安装/使用/维护方法有真实依据；对比变量和不变量清楚，晴雨不暗示未经支持的耐候、昼夜不使无灯商品发光。分格不新增资产。
- 每条具体主张有能支持该主张的证据，不仅是一个看似存在的 ID。
- 产品事实和单位在各文件一致，原始值与换算关系可解释。
- 素材全貌/局部身份及尺寸归属的歧义已通过弹框澄清或仍明确待答；不按上传顺序猜角色。整体值只绑定完整商品视图，局部窗仅使用有独立依据的部位尺寸。
- 容器图不仅总高自洽，主体/露出裸茎/插入分段也守实物比例；外高和有效内深分开，端点不穿底/漂浮；未暗中剪裁、放大穗头或压缩裸茎。每个产品–载体配对独立核对，算术通过不替代目视。
- 多颜色/产品的售卖身份与单一/混放规则已确认，或相关资产仍阻塞；逐载体内容、附件、数量守恒与提示词一致，不把替代用途重复视图误当同时摆放，不因多色增加11图预算。
- 每条 prompt 的可见文案与 brief 一字不差；身份、版式和光影规则自包含。
- 断行拼接还原exact_text（只允许空白变化），数字与单位/否定条件没有拆散；每段只对应一个字区与样式，文字地图和最终TXT一致。限定、售卖边界清楚；拥挤时无静默删锁定词、缩成微小字或让生成器改稿。
- 五张 A+ 图明确映射模块/图槽或列待确认；原生文本不被意外画入图。
- 每个竞品有分区读取覆盖率；视觉结论有真实目视依据。每图有具体排版与光影，不只写“高级、漂亮、真实”。
- 盘点不等于逐图观察；more-images 未展开、A+ 未加载或只见缩略图时不能称全部读完。检查点已记录剩余任务，续跑不重复完整采集。
- 所有引用指向实际来源；竞争资料不被当作我方产品图源。
- blocked 文件不混进可直接执行的说明中；每个阻塞说明所需信息与影响。
- 竞品套图对照与库检索先于来源版式选择，素材/事实澄清无需等待研究完成；以多轮弹框覆盖逐张必要决定，已选或明确委托的项目不重问。每图可追溯来源→选择→骨架→Brief→TXT→总汇；整体风格确认不能掩盖未决细项，无pending选择被冒充confirmed。
- 总汇正文与单张TXT逐字一致，含上传顺序及状态条件；只将READY/PROVISIONAL编入可执行段，BLOCKED独立列缺口/链接，无PDF或让Lovart自行猜排版的总控制词。
- 没有声称已生成图片、读取完整受阻页面、拥有数据工具权限或完成实际市场实验。

## 总提示词汇总与可重复编译

固定的11张prompt仍是事实来源。新增 `prompt-manifest.json` 作为编译清单，每条记录：

```json
{
  "assets": [
    {
      "id": "DIM01",
      "status": "READY",
      "prompt": "prompts/DIM01.txt",
      "references": ["product-front.jpg — product identity", "measurements.jpg — verified dimension endpoints"],
      "condition": ""
    }
  ]
}
```

示例只说明单条结构；实际清单必须恰好11个唯一ID，不能把示例文件名当成真实素材。`references` 按实际上传顺序填写文件名及角色，必须与prompt内部映射一致；无需附件才填空数组。PROVISIONAL与BLOCKED必须给出 `condition`。BLOCKED路径为 `prompts/blocked/<ID>.txt`，正文以 `CONDITIONAL DRAFT — NOT READY TO GENERATE` 开头；其余路径为 `prompts/<ID>.txt`。

在技能目录运行：

```powershell
python -X utf8 scripts/build_prompt_summary.py "E:/Amazon_skill/outputs/<product-slug>"
```

脚本按DIM01、DETAIL01、SCENE01–04、APLUS01–05排序，从单张TXT原样读取，输出根目录 `all-prompts.md` 和 `all-prompts.txt`。Markdown每张一个可复制代码块，TXT每张有明确BEGIN/END边界；每张前列状态、剩余条件和上传文件。BLOCKED只在末尾单独列资产、缺项和条件草案链接，不复制其正文。全部受阻时汇总仍有11项缺口，无可执行段。

这两份合集不算新增图，不替代单图文件；修订单图后重新编译。无Python时可人工做同样汇总并核对全文。编译仅检查ID/路径/就绪分隔与复制一致，不证明事实、文案、版式或实际成图合格。交付时优先给用户总汇入口，再链接索引与策略，不要求用户从PDF提取文本。
