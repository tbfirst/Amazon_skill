# 并行竞品浏览与 Amazon 读取恢复

可用时先参考[画廊采集接入](competitor-collection.md)复用amazon-variant-gallery-scraper的公开图片与manifest。它可采集画廊和A+图片；按当前安装版本的互斥/并发契约执行，不能沿用旧版“一律串行”或假定所有版本可并发。评论仍需独立读取。A+原生文字只在实际采集到独立字段时算可读，不由下载的图片数量推断。研究结束按[图库增量流程](reference-library.md)去重收录与逐图识别，不能把下载数记为已目视数。

## 输入和任务分配

接收 3–6 个不同的 ASIN 或商品链接，默认美国站。规范化并去重，保留原始链接、请求 ASIN 和最终落地 ASIN；截图中同一 ASIN 重复五次仍然只算一个竞品。不同变体、父子 ASIN 和广告推荐商品不能混为同一个目标。数量不足时先分析已有目标，在当前会话一次提出补充需求；不编造其余竞品，也不静默用别的商品替换。

先检查可用搜索、浏览器和代理能力，并读取适用的已安装技能/API 说明。每个竞品使用独立标签页或浏览器会话，记录 ASIN → tab/session → 研究文件的映射。独立导航/读取可并行，默认同时 2–3 个，以宿主限制为准，3–6 个目标分批覆盖。当前只有一个浏览器提供者时使用多个独立标签页；不要把它描述为多个浏览器进程。

在支持并行子代理的宿主中，可把每个 ASIN 的只读研究交给独立研究代理，遵守实际并发上限；每个页面只有一个操作负责人，各代理只写自己的 `competitors/<ASIN>.md` 和同名 `.json`，由主代理汇总。没有该能力时，由主代理批量调度独立标签页。若工具共享鼠标/焦点或会串行排队，串行完成必须聚焦的动作，保持其他独立读取并行；不能把串行执行声称为真正并行。

不要写死一个浏览器工具名称、调试端口或选择器。使用本次工具文档公布的接口，依据当前 DOM/截图定位元素。工具或技能不可用时说明具体限制并使用可用的公开检索路径；不自动安装扩展或第三方爬虫来假装可用。

## 执行顺序与续跑

不要先把第一个竞品研究到耗尽，再开始第二个。使用三轮分批调度：

1. **身份轮**：所有目标先打开并核对站点、请求/落地 ASIN、标题和选中变体。记录时间和标签页句柄。错误商品、跨站点跳转或未选定变体先隔离，不能继续当目标分析。
2. **视觉轮**：每个可读目标先盘点图库和 A+，再按下方步骤检查；一张图的导航与观察顺序不能并行乱序，不同目标的独立动作可以并行。
3. **需求轮**：先检查商品详情页内嵌评论与买家图片，再按需尝试完整评论列表，整理搜索线索后汇总。两条评论路径分别判定；某条路径需要登录或受阻，不抹去另一条路径已取得的原文，也不影响已完成的视觉轮。

每区完成或受阻即写 `competitors/<ASIN>.json` 检查点，并更新对应 `.md` 的实质结论；记录规范见 [research-records](research-records.md)。主代理独占汇总文件，研究者独占各自 ASIN 文件。批次等待必须接收全部成功/失败结果（如宿主支持，可用 allSettled），不能因为一个拒绝丢掉其他成功结果。逐步保存，不依赖浏览器历史充当研究记录。

续跑先读检查点，验证现有标签页 URL/变体仍匹配，只补 pending/partial/受阻后已恢复的部分。会话丢失时从记录的已验证 URL 重新定位，重新检查身份；不复用失效元素索引。用户换站点/变体或页面发生明显变化时新建观察版本，保留旧来源日期，不混用为同一时刻数据。

正常并发从两个独立标签页起步；第三个只在接口稳定且无共享焦点争用时加入。连续出现接口超时则暂降为一个，先完成一个区再恢复并发，不增加浏览器数量来掩盖超时。每个长操作完成后及时汇报新的结果；不要让研究队列阻断必要的用户沟通。

## 每个 ASIN 的恢复顺序

1. **明确身份与入口**：使用用户链接或同站点规范商品页。搜索/网页读取工具可并行收集文字，但视觉分析必须打开并看到图片。
2. **正常浏览器页面**：网页工具返回 Cache miss、空壳、403 或抽取失败时，在实际浏览器打开商品页。导航超时后先检查标签页当前 URL、标题和可读 DOM/截图；页面可能已加载，只是工具没有等到加载完成。不要立刻刷新丢弃已加载内容。
3. **恢复观察接口**：无障碍快照超时或过大时，按该浏览器公开 API 改用 DOM 快照、已知区域的可见文本和截图。正文可读时只读相关区域，避免反复输出整页。不能读取隐藏应用状态、注入修改脚本或猜内部接口。
4. **换正常公开入口**：身份页确实没有打开时，用 Amazon 站内搜索该 ASIN，或一次精确的公开搜索 `ASIN + Amazon + 站点`，检查最可信的候选，沿实际可见链接进入。必要时使用页面上可见的品牌店入口核对。不得循环枚举猜测 URL、代理站或跨站点替代同名商品。
5. **分区恢复**：从页面真实的缩略图、详情/A+、评论导航进入目标区。滚动或点击让懒加载内容出现后重新观察。评论先检查详情页内嵌区，再尝试完整列表入口；完整列表受限时保留内嵌原文、详情与图片，不把整条竞品或整个评论区判为失败。
6. **到达访问边界**：遇到真实验证码、登录或权限要求，按宿主确认/接管规则处理；不把“自行解决”解释为绕过访问控制，不使用凭据抓取、代理轮换或禁用安全设置。继续其他竞品和公共部分，只有剩余缺口确需用户动作时才请求该动作或最小资料包。

每种恢复必须有新的依据或路径；同一无变化失败不要盲试。一个页面的合理路径耗尽后，记录步骤、错误类别与剩余缺口，继续其他竞品。不得承诺任何 ASIN 永远可读。

当前竞品的视觉恢复耗尽后，按[内置套图回退](reference-library.md#套图查找与竞品失败回退)展示历史成图并弹框选择布局，继续可完成的策略与prompt。LIB来源保留自身日期/范围，不替代本轮V覆盖或评论、关键词证据；有事实缺口的资产仍按真实条件处理。

### 分类恢复与停止条件

| 实际信号 | 下一步 | 何时停止该路径 |
| --- | --- | --- |
| 导航超时，但 URL/标题已落地 | 检查正文或截图；无需再次 goto | 能读所需区域即继续业务，不再纠缠 load 完成 |
| AX 超时/整页快照过大 | 一次改用文档支持的 DOM；后续只取目标区文本/截图 | 同一区域两种观察接口均失败，记录工具限制并切其他正常入口 |
| 点击后图未变化 | 重新观察选中缩略图、弹窗/加载状态，按新状态纠正一次 | 仍无新画面则记该图未读，继续其他图；不能把旧截图算成新图 |
| 空白图片/懒加载 | 通过正常滚动或已见控件使区域可见，再观察一次 | 仍不出现记 partial；不靠 alt 文本填视觉结论 |
| 错误 ASIN/变体 | 记录跳转；沿页面真实选项寻找请求变体 | 找不到即标身份未核实，不研究另一个商品冒充目标 |
| 页面不可用/404 | 站内搜索或一次精确公开搜索验证目标 | 未找到同站点正确商品则结束该目标，保留其余目标 |
| 登录/验证码/访问拒绝 | 标实际受限路径；完整评论列表受限时保留详情页已读顶评，未检查内嵌区则回到正常商品页检查 | 停止受限路径，不重复撞墙；不尝试隐藏接口或绕过验证 |

数字是避免空转的恢复预算，不是采集图片数量上限；新证据、用户完成登录或主动要求重试时可以继续。预期缺口不是脚本错误，也不需要整项目停止。

## 图库逐图步骤

1. 从当前 DOM/截图识别目标商品的图库容器及缩略图，记录图片、视频和“更多图片”入口；不统计推荐商品。
2. 先看当前主图；再逐个打开图片缩略图。每次动作后检查选中状态和大图是否变化，然后目视分析。仅有缩略图预览不算已读大图文字。
3. 存在 `3+`/`4+`、全屏或更多图片入口时，按实际可见控件打开；确认 Images/VIDEOS 分类和当前变体。展开后重新盘点，不能把按钮上的数字当总图数。
4. 为每个可见图位登记稳定来源定位（图序+图像URL/已见控件/截图之一）和状态。相同内容的缩略/高清版本只算同一视觉证据；不同图片不可因文件名近似而合并。
5. 对全部可访问独立静态图做一次快速检查，对尺寸、细节和场景代表图做详细记录。文案太小或图被遮挡时用正常放大/全图视图；仍无法读清就标 unreadable，不猜字。
6. 结束时报告“已详细查看 n / 已盘点 m 张静态图”，附未查看项理由。没展开的图库总数记 unknown；不可写“全部图片”。

逐图记录之外，保留该ASIN的有序套图图谱：顺序、V-ID、功能、布局骨架、文字密度和跨图共用规则。区分单幅实景与一张内含多景的拼版，比较尺寸/细节/场景的相互节奏。缩略图红框或网格只表明有更多图，不证明其布局已读。视觉轮完成后将实际可用来源交给[版式弹框](set-layout-dialogue.md)，评论受限不阻止用已读视觉资料讨论方案。

## A+ 逐区步骤

通过已观察到的 Product description / From the brand 等页面入口定位。它们可能包含 Brand Story、原生文字、图片、轮播和比较表；按页面实际内容区分，不由标题断言模块类型。

先建立区段清单（自上而下），再正常滚动让每个区段加载，定位模块边界和下一节（例如 Product information）。懒加载图片、轮播隐藏页、移动端版本不能凭 DOM 中存在就算看过。点击轮播仅检查实际需要且可见的控件，保存顺序与定位。

每模块记录“页面布局”和“图片本身布局”：原生四列图文模块不能被误判为一张四宫格大图。分别记录模块用几个图片槽、哪些标题/段落属于原生文字，无法确定的标待确认。竞品展示尺寸只能启发构图，不是我方 Content Manager 的上传规格。

保存每次出现的位置而非只存一个UUID：源ASIN/URL、product_description或brand_story区段、模块序号、模块内图片序号、实际变体范围、来源方法和采集时间。相同媒体文件可以只存一份，但其多次模块出现与来源范围必须保留。HTML URL首次出现顺序只能记为回退线索，不能冒充已核验模块顺序。

为A+模板逐图确认主要产品身份，写`principalProduct`（id、label、reviewStatus和目视范围）。来源ASIN用于分区，不证明画面中的主要产品；品牌故事/比较表可能出现其他商品。同一主要产品的一组图共享一个模板入口，切换参考图时使用与该图对应的完整提示词；不同主要产品即使背景和版式相同也分开。不确定、残片或多产品图先留待复核，不能用“家族共用”填身份结论。

全部可访问区段检查完成才能标 observed；只看到页头横幅或中间一屏必须是 partial。没有发现 A+ 时，只有检查了相关区段并记录边界和页面状态，才可标 absent；未加载、未定位或工具受阻均不能写“没有 A+”。

## 评论与买家图的采样步骤

按以下顺序检查，两条路径分别记录来源、状态与停止理由：

1. **详情页内嵌原文优先**：在已核实身份的商品页定位 Customer reviews / Top reviews 等实际区段，通过正常滚动使评论区及其下边界出现；有 Read more / See more reviews 等控件时，依据实际落点区分展开正文与跳转完整列表，先读取可展开的内嵌正文。不能因首屏无评论、整页正文/AX快照截断或页头有 Sign in 就判登录墙。长页面改用目标区文本、DOM或截图；DOM选择器须依据本次实际页面，不写死为永远有效。工具允许直接读取公开商品HTML时，可提取其中实际存在的评论正文与ID，但不得猜内部接口或把脚本占位符当原文。只有HTML可读时记录此来源，不声称已目视买家图。
2. **完整列表补充**：保存内嵌样本后，按需沿页面实际的 See all reviews / 筛选入口继续，不猜评论API或新URL模式。登录、验证码、守卫跳转、403/503和工具抽取失败分别照实记录；重定向或请求失败本身不等于登录要求。列表受限只停止该路径；若尚未检查详情页内嵌区，回到正常商品页检查。移动布局折叠时先用已见控件展开；工具支持正常桌面页面时可检查一次，不能由移动布局推定所有匿名访问均不可读。
3. **按实际样本交付**：优先读完详情页当前公开的独立顶评，数量按实况，不固定为8条。首轮总预算仍为每竞品 **最多30条独立原文**，这是上限而非最低数量；完整列表和筛选器可用时，再补最多10条低星（1–3星）、10条高星（4–5星）、10条近期评论，含已读内嵌样本且总数不超预算。去重后不足即按实读数交付。只有顶评时写明“详情页公开顶评、页面默认排序、采样日期、N及完整列表状态”；不声称覆盖近期或低星筛选，也不为凑30条要求登录/导出。确有策略缺口需扩大时再说明缺口与追加来源；这不是统计代表性承诺。

只有评分分布和 Customers say 摘要、且未取得原文时，原文样本 N=0；AI摘要单列。已有原文而完整列表受限时，总体 `reviews` 用 `partial` 并保留 N 与采样说明，不能写 `access-blocked` 或清空样本。仅详情页公开采样范围明确完成且没有待补范围时可用 `observed`，也不表示全部历史评论已读。两条路径均未取得正文时，区分真实访问限制、未定位/未加载和观察工具失败；后两者不能冒充登录墙。

记录评论 ID/稳定链接、日期、星级、变体范围、排序/筛选条件、简短忠实摘要与主题。跨 ASIN 共用父商品评论池时同条评论不能在汇总中重复加权；全局频次先去重，并单列变体不确定样本。不要把人为平衡抽样的比例解释成总体差评率。

买家图首轮优先最多5组与身份/尺寸/到货形态有关的照片；每组尽量关联原评论和变体。照片无法关联原文时明确未知，不推断其是否购买验证。用作“卖家表达与买家呈现可能有落差”的线索，不能据单张曝光/拍摄差异证明材质欺诈。

达到工作预算或可读样本耗尽即停止采样；遇到访问要求只停止相应路径，检查另一条尚未检查的正常公开路径后，报告实际覆盖和理由。新主题是否需要追加采样由其对11图策略的影响决定，不因“还可以抓更多”无限抓取。

## 分区采集与视觉记录

每个竞品分别检查并报告：

| 区域 | 采集与分析 | 完成标准 |
| --- | --- | --- |
| 身份 | 请求/落地 ASIN、站点、标题、品牌、当前选中变体、含盆/件数 | 与目标商品对应；跳转和冲突有记录 |
| 图库 | 当前主图与可访问副图；尺寸、细节、场景、信息图分类 | 实际打开看到图，记录图序/缩略图或链接；不由标题猜构图 |
| A+ | 页面可见模块与图片、信息顺序、图文分区、风格一致性 | 区分图像已目视、文字仅可读、未加载与未发现 |
| 评论图 | 买家图片呈现的尺寸、颜色、密度、到货形态与卖家图落差 | 核实关联评论/变体，数量按实际看到的计数 |
| 评论原文 | 抱怨、惊喜、误购和请求，样本数与主题频次 | 分列详情页内嵌/完整列表的覆盖，只统计实际读取且去重的正文 |
| 搜索需求 | 公开词语/搜索观察及已有报表 | 不把标题词或平台 AI 摘要当成自然流量数据 |

同页的推荐商品、广告、视频封面和其他变体图片分开标注，不纳入本 ASIN 图库计数。平台 Customers say/AI 摘要可作单列线索，不能充当读过的评论，也不能用其中括号数计算自己的样本频次。

为实际目视的每幅代表图建立 `V-<ASIN>-G01`（图库）、`V-<ASIN>-A01`（A+）、`V-<ASIN>-R01`（评论图）记录：来源 URL/页面区域、观察日期、关联变体、图像类别、观察到的布局、主体占比、文字层级、背景/道具、视角、明暗/光向/阴影、优点、误导风险、可迁移原则与适用我方资产。占比与光位只写视觉估计，不声称拿到了原始摄影参数。

若宿主支持保存截图，用研究项目的 evidence 子目录保存并链接；不为此绕过工具限制。不能保存时保留页面 URL、区域/图序和实际观察说明。没有看见图，只能写文本结论，并将布局建议标成“独立设计建议”，不得加伪造的 V 证据。

## 单竞品研究文件与汇总

`competitors/<ASIN>.md` 至少包括：

```markdown
# 竞品 ASIN
Requested URL / final URL / variant / marketplace / observed date:
Browser session / tab / researcher:
Coverage: identity | gallery | A+ | review photos | review text | search data
每区状态：pending / observed / text-only / partial / access-blocked / not-observed / absent
Recovery log: 路径、实际结果、下一步或停止理由

Visual records: V-ID、图序/区域、观察、优缺点、可迁移原则
Reviews: 详情页内嵌/完整列表各自状态与来源；实读 N、主题 n/N、排序/筛选、采样日期、反例、变体局限
Search observations: 已知数据与未知字段
Useful for our images: 对应 DIM/DETAIL/SCENE/APLUS ID 与理由
Outstanding gaps:
```

主代理逐个验收返回结果，检查覆盖率、变体和证据真实性，再写入 `design-strategy.md` 的竞品对照表。区分多家共同使用的表达、个别有效例子和自己的建议；没有销售实验数据时不能说某种排版“转化最高”。用户要看分析结果，不能只交付链接或一句“已分析竞品”。

## 已验证的恢复案例

2026-10-16 对此前网页工具 Cache miss 的 B0H2LZNL5H：浏览器首次导航和通用状态接口超时，但实际标签页已落地；通过浏览器文档支持的 DOM/可见正文与截图读到了商品页。详情/A+ 文字可读，当次观察的评论原文区显示要求登录。历史记录未分别核实详情页内嵌顶评与完整列表，不能据此推断该商品没有公开顶评，更不能推广为 Amazon 评论一律需要登录。这证明需要分区恢复，不证明评论已读取或所有图片已验收。它是方法验证，不是新项目的默认竞品。
