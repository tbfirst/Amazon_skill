# 从商品任务主动拓展场景

沿用植株版“先研究与拟候选，再弹窗选择”的分析顺序，场景内容改由本SKU用途、对象、形态和支持条件决定。技能主动提供候选，不让卖家替我们列四个房间或节日。

## 每项目的四项主动设计评估

所有商品套图项目，无论竞品、内置、混合或原创路线，都在最终分配资产前主动评估下表。竞品有相应画面可借鉴，没有也须根据本品用途与素材提出D设计候选，不能以“竞品没出现”直接略过。仅采集研究不强套生产设计；旧套图刷新在已定范围内评估，不擅自增加图片。

|维度|需要给出的具体候选|合理不采用的情形示例|
|---|---|---|
|多角度|与买家问题对应的正视、俯视/高位、侧视、近拍或交互视点；写明展示的真实表面、景别及素材依据|新增角度只暴露未知结构、无新增理解，或已锁定同机位比较|
|多场景|不同任务、空间关系或使用阶段，写出场所、使用者/对象、动作、状态与环境锚点|用途或本次范围窄；同条件步骤/比较需要保持环境。不能只换墙色和房间名|
|本品道具与主题图形|实体物件与线描/卡通/剪影/主题符号分别提出具体对象、用途、位置与从属层级；有字时说明与哪段文案配合、如何引导阅读|物件会误导随货/适配，图形缺乏产品关联、造成信息噪声，或用户明确要求无装饰。不能因为无字就禁止主题图形|
|早晚时段变化|按真实用途提出晨间/日间/傍晚/夜间的具体活动、主光、冷暖、明暗及接触/投影关系；可分图或在已定拼图内比较|使用价值不随时段变化、暗部妨碍识别、画面暗示未知照明功能，或已锁定统一光线。不能只加两个滤镜冒充早晚|

在layout-decisions保存简短的`designOpportunityReview`：维度→具体候选或不采用理由→本品依据/设计来源→采用、未采用或待决定→理由→目标ID/格位。道具与主题图形分别记决定。每个维度都需有实质判断；“按需”“不适合”“竞品没有”本身不是有效理由。有候选但尚未决定时保留pending，不擅自写成已采用；已获设计委托则自主选择并说明取舍，不逐项重复询问。资料不足写明受影响候选及补证需求，继续可支持的方案，不造未知表面、动作或适配。

评估是必须执行的步骤，四种表现并非每套或每张必选。可以多项合并到一张，也可以不采用某项；不为凑数破坏信息任务、真实尺度、已有无字决定或既定预算。reference-replace仍保留选定源图，未获授权不自动换机位/场景/光线：将新增机会作为替代源或修改提案展示，复用已有委托；用户决定保真时记录未采用原因，不暗中改稿。

采用项继续逐图深化，只有具体对象、位置、机位、环境、时段/光影或图文关系已经确定，才进入对应独立prompt；正文不保留候选清单及评估过程。交付前反查每个采用项是否进入目标图，未采用项是否有有效理由，并按整套尺度约定检查对象体量；不因追求丰富而混入不一致的使用者。

## 从评估到候选选择

1. 从P事实和已看套图、评论/关键词意图里找有价值的使用任务、摆放/操作关系、选择障碍。先分已证用途与设计假设，不能为了多样性新增功能。
2. 按相关的地点、使用对象、观看距离、时段、活动、操作阶段、配套对象做候选矩阵；这些维度不是四张图的固定配额。住宅、办公室、车库、工位、通勤或室外按用途选，室内限制就明确排除室外暴露。
3. 参考重复或不足时，做有界的公开灵感检索，实际检查少量适配来源。记录query/URL/读取日期、正文或图像的实际覆盖、可借结构及排除理由。来源记SRC-INSP，与P/V/R/S分开；文本启发的画面是D提案，不号称已看原镜头。
4. 逐候选核“商品—环境、配套物—环境、商品—配套物”三组关系：真实尺度、接口/容纳、支撑、动作、环境限制和视觉主次。随货组件保持身份，未指定可选道具可由已授权设计决定，不为每件物品再问。
5. 给用户2–3个具体、有实质取舍的候选，再按[场景问答](scene-types.md)确认类型、ID、像素和细项。不同单景以新增任务或空间叙事区分；步骤靠真实信息递进，对比靠有据变量，不硬换房间。

每个候选记录task/location/state/support/scaleBasis/props/light/source/decision/reason；只保留会影响本项目的字段。使用西方市场场所时写明实际建筑或环境锚点、可见远景边界及自然照明，操作近景不硬塞住宅全景。季节/场合只改变环境时，产品本色、组件和销售内容保持一致。

A+同样可用适配场景、室外或操作方向，数量与画布仍按A+范围。不得因参考偏室内就给A+设室内配额，也不能把户外摄影当耐候证明。配色/机位、接触/投影与逐元素文字按既有美术和尺度记录展开，最终prompt只写唯一选定画面。

## 整套差异检查

差异与一致性一起核对：按[整套尺度与适配一致性](scale-consistency.md)检查所有相关资产及每格；多角度、昼夜和多场景改变视觉叙事，不改变同一SKU的尺寸或无依据扩大使用对象范围。DETAIL/A+里的小区域同样不能混入不同体量/规格的对象。

将SCENE与场景型A+放在同一表中检查，避免附图各换房间名称、A+又重复同一张全貌。每个候选明确：买家任务、使用对象/动作、产品状态、场所/建筑锚点、实体道具与平面点缀、相机高度/侧向/景别、背景关系、主光/反差与阴影、身份素材依据。无动作/无图形可以，但应是本图任务或已选参考的结果。

先按上传多角度建立可用视点表：正面/侧面/高位/局部/已知开合状态能展示什么，哪些角度会暴露未知结构。商品有可靠多视角时，主动给对应任务选全貌、正视、俯视/高机位、近拍或交互视点；不把身份主图的角度锁成整套唯一机位。支持范围内换机位不需要重新证明未改变的商品事实，未知背面/内部则补证或换可证视点。相机与商品朝向、实物大小分别记录，不靠旋转整间房或拉伸商品制造差异。

对近似重复的两图，说明各自新增了什么理解。只改墙色、加一种滤镜、换房间名而主体落点、视点、动作、道具关系和光线都相同，应重新选源或提案；不设机械的角度/颜色/室内外配额。步骤对比可刻意保持机位与环境稳定，品牌系列也可共享风格，记录比较目的即可。reference-replace优先保留已选源图，不为凑多样性改坏参考；若选中来源本身重复，展示替代源图并问用户选重复保真还是换源，不暗改。

最终展示的是**具体而不同的候选**，不是让用户自己想四个场景。除空置外，按真实用途优先考虑使用、休息/操作、装填/取用、人与物关系等适用状态；纯外观产品则靠展示任务与可证视点变化。实体装饰、主题小图形按[角色区分](scene-props.md#分开四种角色再决定画什么)辅助，不用平面点缀冒充实际使用图。
