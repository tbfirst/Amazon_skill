# 已有套图更新

先列旧图ID、文件、现有角色、能确认的商品事实、可用产品区域、设计问题和缺少角度/细节。把用户要更新的实际图记入targetAssetIds，不自动扩成11张；旧MAIN在范围内才处理。角色不确定先问用途，不靠画布猜。

默认layout-rebuild：保留支持的商品本体与事实，重新判断旧图的布局、文案、场景/道具、配色、机位、光影；用户锁定项优先。只有明确限定修改时用bounded-edit。更新旧设计与继承新选竞品布局是两件事，可以同时成立。

研究真实竞品后，先按[参考选择弹窗](discovery-layout.md#采集后的参考选择弹窗)确认尚未决定的具体套图/图位。用户已说按竞品更新就沿用competitor-derived，不重问三条路线；未指定时可选内置或具名混合。展示来源后按[继承强度](reference-fidelity.md)落实reference-replace或structure-adapt、覆盖ID和例外；已有“只换本品、小改”等直接复用。重做旧稿不等于重做新参考。每图在`set-refresh-map.md`记录：旧文件→新ID、旧问题、保留商品区域、删除旧字/背景的指令、选中参考、保留的信息关系、具体改造、新布局与文案、补图要求、状态。

旧图可能有夸大的效果或错误尺寸。用户要求保留不等于支持该事实，指出具体冲突并确认。低清部件无法靠锐化提示词证明结构，缺少正确信息的依赖资产blocked；不影响其余图继续。

分别审计旧→新是否真的完成所要求的重排、选中参考→新是否保留承诺的布局关系。只换滤镜或加标题不能冒充重建。脚本/提示词审查不等于实图已经改变。
