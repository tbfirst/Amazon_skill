## 竞品图片零持久化与ASIN去重（优先规则）

本规则覆盖本技能中保存竞品图片、截图、联系表、图片manifest或上传参考副本的旧约定；用户自己的SKU实拍不属本规则。

- 永久研究状态仅保留技能目录外的一份ASIN去重表：`D:/codex-off-project/amazon-crawled-asins.json`。迁移宿主时沿用同一表或用户指定路径，不另建分批表。表只含站点、ASIN、类目、分析日期与状态，不含图片、base64、图像URL、文件路径或页面快照。
- 每次发现候选先读取表，按站点+ASIN去重；表内skipFutureCrawl=true的竞品直接跳过，不再打开详情/抓取媒体。当前会话的父子ASIN别名也先合并，不以换变体重复计数。
- 竞品图片只允许通过当前会话可见浏览器或内存字节流临时查看。不得写本地、临时目录、下载目录、技能assets、项目图库、浏览器持久缓存、截图/联系表、上传副本或base64日志；关闭下载和持久浏览器profile/状态。工具强制落盘时不要直接运行其下载模式，应使用不落盘的浏览/内存读取方式；不因旧采集器默认行为而保存图片。
- 会话中实际看图、理解整套关系并完成具体反向提示词后，再把该ASIN原子追加/更新到唯一去重表，然后释放内存图像、关闭本轮页面和非持久浏览器上下文。失败或未完成分析的候选不能标记已完成。
- 长期可保留的是反向提示词与文字设计结论，不保留竞品图像证据库、逐图媒体URL/哈希manifest或下载恢复点。中断后靠ASIN表跳过已完成项，未完成项不假称已看。
- 最终提示词须自包含地写出构图、机位、光影、色调、道具和文字关系；不要求重新上传已丢弃竞品图，不引用已删除文件，不写“照参考图”。实际生产时只引用用户仍可提供的本SKU身份资料。研究文本与生产READY分开，未生图不声称验证通过。

# 从优秀源套图到本SKU的一套设计

用于用户要求“像这套一样好，但有自己特点”，或批量研究需形成可用整套方向时。先按 [套图规划](campaign-planning.md) 的购买任务与实际范围工作，再逐图编写prompt；不是给图像模型一句“生成整套”。

## 套级决定先于单图美化

保留两条顺序：实际源gallery/A+顺序，以及目标套图的阅读顺序。逐图来源记录不能被重排抹掉。先看源套如何从识别、细节、用途、条件、选型走到购买判断；哪些关系有效、哪些重复、哪些只是品牌跨售/订阅/不匹配变体。不要把下载的每张包装角度都当成一个新的生产资产，也不因研究有13帧就更改默认11资产预算。

写一张套级方向卡，直接放入现有design-strategy/layout-decisions或研究set卡，不另造繁重交付体系：

- `sourceSet`：所选ASIN/变体与实际源文件，gallery/A+/Other/品牌故事分别覆盖；Other不是无A+。
- `sourceRoleSequence`：每帧的主问题、表达方法和叙事位置；未证功能、其他SKU和历史包装分别记。
- `targetNarrative`：本SKU要回答的问题及目标顺序，与来源角色的retain/adapt/omit/unresolved映射。调整任务说明为什么；缺功能证据时保持原问题未解决，不能换个caption就说已回答。
- `setStyleLock`：一个确定的环境/文字色板、字形层级、边距/引线语言和摄影光线基调；原包装/商品本色独立锁住。统一不等于每图同底色、同机位、同光或都用信息卡。
- `perAssetVariation`：每张继承的分区/阅读关系，以及明确改变的配色、构图、已有证据支持的机位、光影、从属道具或字形；共同值要写进各条prompt，不写“沿用整套”。

学源套的有效区别，而非只学同一种通用极简感：床单源套无字实物图→末尾数据页的轻重节奏值得保留；活泼零食套图可保留大胆字级与照片/图形交替，用原创几何替代品牌卡通，而不是全变米白静物；多配置支架先讲内容、安装条件、手机/壳/环再讲动作，不能把多个承重广告当四个不同购买问题。

## 给策划agent的可复制主提示词

下面是**策划指令模板**；输入字段允许待填，但它不是已READY的生产生图prompt。最终单图执行正文不得留变量或研究工作流。

```text
请根据我提供的本SKU资料与实际参考套图，完成“有可见参考继承、又有自己设计特点”的整套策划，最后产出每图独立的英文Lovart提示词。先做套级方向，再逐图展开。不要把这条主提示词当作给图像模型一次生成多张的指令。

输入区：
1. 本SKU身份与售卖范围：产品/变体、实际外观与颜色、销售单元和附件、实拍文件清单、尺寸/规格及其测量状态、已证功能与限制。缺项写unknown；用户历史资料和已明确委托沿用。
2. 项目范围：new-set / set-refresh / ranked-reference-study；明确已有targetAssetIds或实际源图范围。new-set默认11资产，研究不强套11。目标站点与用户已确认的画布、文字/字体/场景设计委托。
3. 参考套图：ASIN/父子变体、实际文件/URL、原序号与区段、实际目视覆盖、主要产品身份、主套图与辅助参考各自负责什么。辅助源不拼成目标SKU事实。
4. 继承目标：保留哪些有效的信息关系、分区/阅读顺序、主体占比、照片与图表节奏、细节对应和光影特征；希望重做哪些环境色、字体、机位、布景或从属道具。未指定时提出一个确定的参考启发改造方向，不交仅换产品版本。

工作：
A. 核本SKU事实与输入角色。分别锁定商品身份和整套设计；每个实际上传文件说明identity/detail/dimension/state/layout/style角色，不把源商标、别的商品、跨售、订阅或历史包装当本品。
B. 实际看源套后，列原顺序角色图谱：源序号→买家问题→有用表达→可迁移关系→本SKU适用条件。没有看图不写布局；A+/Other/品牌故事按实际来源分开。
C. 给出目标整套阅读顺序与一张风格锁：一个色板及用途、字形层级、边距/引线规范、光线与材质基调，以及每图应变化的景别/构图/文字密度。保留源套有效差异，不将摄影、尺寸表、背标和跨售一律改成生活场景或同款白卡。
D. 逐资产写“源任务→目标问题/有据答案→保留关系→具体新变化→实际附件→缺口/状态”。源功能缺证时保留未解决问题或条件brief，不能用更换caption、删数字或另做氛围照片宣称功能已继承。设计变动不能造未知背面、内部、接口、用量、件数或测量。
E. 按实际范围输出中文策略/决定与每图独立英文prompt。每条包含实际输出规格、按上传顺序命名的真实文件与作用、本SKU锁、已定构图/尺度/状态/支撑、光影材料、精确文字/排版或无新增字。整套共同色板/字形等值在本条展开，不能写“同上”。只把该图相关约束写进执行正文；研究、状态、证据ID和“先查资料”等留在brief/索引。
F. 做两次对照：先源→目标，检查信息关系和有意差异；再整套→单图，检查身份/色板/字形一致、相邻资产各有新增问题、摄影与信息页节奏、功能/规格/数量条件无漂移。核所有实际上传文件存在且顺序匹配。未生成图只标design-checked; render-unverified。

缺资料时继续不依赖缺项的资产，明确依赖图的缺口。无用户SKU时仅交源套分析、STUDY_VARIANT研究练习、ADAPTATION_RECIPE映射和套级候选，不假装生产READY。明确用户授权后才执行另行生图；本次只做策划与提示词。
```

## 单图正文与整套对照

共同风格锁存在文档里还不够；最终每条要包含实际选定值并排除冲突旧值。例如一套已选石墨标题与灰蓝引线，单图不能仍留橙色大字/金色圆窗指令。对于透明/白色商品，环境/文字改色而商品不改；平面表格不改“机位”；无字图不因统一字形而强加标题。

最后核对每个源角色在目标中是有据回答、明确适配、范围内省略还是未解决。研究源数与生产资产数分别汇总：同一包装的三视角可以合并为身份素材，品牌跨售可以排除，缺证的性能页必须仍在缺口表。至少能看出源套哪些优点延续、哪些具体改变，不能只留下一个泛泛配色或重复产品图。
