# 多轮沟通、文案与逐图决定

`discovery.md`持续保存：项目模式、产品画像/站点、范围、已证事实、被触发的需求、冲突、待补图及受影响资产、当前阶段、下一未决问题。`layout-decisions.md`保存每图的来源、迁移强度、买家问题与表达方式、角色调整理由、布局、场景类型、像素、文案模式、输入原文/润色/最终版、字体、答案与委托范围。状态用confirmed/delegated/proposed/pending，不适用项记not-applicable。恢复项目先读这两份，不从头盘问。

最初只需要识别售卖主体、用途、销售单元与变体，并知道手头有什么证据。其余问题按[商品画像](product-profile.md)和拟采用的图片触发：不问贴纸承重，不问充电线内部净空，不要求只有平铺展示的枕套先提供填充状态。不适用、可选、当前图必需三者要分开。用户已明确的棉质、无枕芯、平铺尺寸等直接记录，不为填表重问。

## 多轮沟通循环

默认主动开展设计共创，轮数随未决事项决定，不限于“先问一次参考，再问一次细节”。每批通常1–2题；用户要求详细讨论时持续深化，用户明确委托或要求直接出稿时按其范围代选。以下循环贯穿事实核对、选参考、逐图骨架、场景、文案、字体直到相关图足够定稿：

1. **读当前决定。** 恢复时先读discovery.md和layout-decisions.md，检查上一批实际回答、覆盖ID及委托；每项设计分别保存状态，不能只有一个“全套已确认”。用户说“AI写文案”通常只解决文案来源，不能自动确认布局、是否加字、字体或SCENE像素。
2. **选下一项。** 先解决会影响当前图的身份/事实歧义，再选一个尚未确认且会改变成图的设计决定。按依赖关系推进：参考路线/来源 → 该图骨架与内容 → 文字模式 → 基础文案/AI拟写 → 字体与文字布局。场景分配/像素按[场景问答](scene-types.md)插入相关图的讨论，已有回答跳过；文案可提前收集，不把顺序当成固定问卷。
3. **展示后实际弹窗。** 先在聊天展示本图ID、任务、真实参考及2–3个有实质差别的可行方案，给简短推荐理由，再调用可用提问工具。用户不需自己翻全部竞品或提供全部场景；技能先分析并拟候选。产品实测值用自由输入，不给猜测推荐值。设计可给“按这组列明方案 / 指定修改 / 这组由你定”，但不能把所有未展示资产一并设为已确认。
4. **等待并保留状态。** 发出后记pending，仅推进不依赖答案的研究/资产；不要在答案前发出依赖它的下一批问题或定稿相关prompt。不以等待超时、关闭或预选替用户作答。独立工作做完仍未回复时，以简短消息说明当前待答项并结束本轮，等回复后从该点继续，不用最终合集代替等待。
5. **回答后解释并续问。** 用一句话说明具体影响，如“SCENE02改为四宫格，将分别展示四种用途；接下来确认各格内容与顺序。”保存用户原答、确认/委托范围和受影响ID；展开委托为具体设计，然后检查下一未决项并再次弹窗。有新歧义就继续问，不因已经问过一两轮而停止。普通语法润色或已授权微调直接完成，不再逐项求许可。
6. **按图收束。** 当前图必要事实、骨架、内容、像素、文字模式、文案来源和适用的字体/排版已确认或已委托且落实后，才可写最终brief/prompt。无字图的文案来源/字体为not-applicable，native-only的字体由原生字段控制。不适用项不制造额外轮次；其他图仍pending不阻塞这张，也不被这张的确认自动覆盖。

### 逐图推进的讨论主题

先用已有资料识别本项目的购买目标、典型使用情境、要完成的任务、替代选择与主要犹豫点，再分配图片。事实不足或用户目标会改变任务排序时逐轮询问，例如这次优先解决误选规格、看不懂内容物还是不会使用；不把这些话题当成全类目必填商业问卷。评论/词表已有线索时先分析再给选项，不让用户重做研究；缺样本只标待验证假设，不假称高频痛点。

|阶段|本轮先展示什么|按回答继续问什么|
|---|---|---|
|DIM01|两种与本品规格/适配任务相符的骨架及真实源图|全貌与参数/适配关系如何安排、是否要特写窗、窗口展示哪个已证部位；未知端点/状态先澄清|
|DETAIL01|拟强调的可见细节、整体与局部的对应方式|特写数量/部位/形状及是否有据的手部操作；不默认做微观纹理或材料性能|
|SCENE范围|按当前N张给有依据的类型分配建议|先定分配与ID，再逐图像素及单景/四格/步骤/对比内容，见[场景问答](scene-types.md)|
|A+范围|按目标ID列出有序版式，例如横幅→结构近拍→使用步骤→适配→内容物|每张对应的源图、实际结构、叙事顺序及例外；组级确认仅覆盖明确展示的项，不自动确认文案|
|每图文字|该图任务、推荐无字/短标题/信息标签/原生文字及理由|先落实是否要字，再收基础文案或AI拟写决定，之后字体/文字区；见[文案与字体](copy-typography.md)|

以上是按需话题，不是要求每张图把每个字段都问一遍。选了整体骨架后，只追问会改变结果且尚未解决的细项；不反复问“是否同意整体方向”。仅回复“不知道”不自动委托，可给具体推荐并让用户选择；产品事实仍保留未知。

### 续聊记录

discovery.md保存`stage`（intake/research/reference/layout/copy/handoff）、`activeAssetIds`、`lastAnswer`、`pendingQuestions`和`nextQuestion`；已定共用风格/场景分配/字体注明覆盖ID，参考路线/主套及库版本分列。layout-decisions.md逐ID分别记录来源分支、继承强度、layout、sceneDetails、canvas、copyMode、copySource、fontChoice和文字地图的confirmed/delegated/proposed/pending/not-applicable状态及实际回答依据。不要为无关商品强填场景动作或内部容量；不适用项说明即可。

新回答若改变已有决定，标出受影响的ID和下游brief/prompt，更新这些内容后继续下一问题；不能保留旧文案、旧像素或旧来源作为并存的执行选项。

## 有用的提问顺序

1. 看素材后确认影响身份/尺寸/功能的事实。比如“尺寸图8×10指适配照片，还是外框？”不给猜测数值作推荐。
2. 首批可用竞品完成看图后，按下节展示真实候选并实际弹窗，确认是否参考，再确认确切ASIN变体、图位与参考程度；不等研究全部结束。已有选择不重复问；无可见竞品则展示有标签的文本方案，不伪造参考缩略图。
3. 确认全套风格，再逐图讨论信息结构。DIM按该产品需要明确测量端点/状态、适配或其他已确认规格，DETAIL选有资料的细节；再确认主次视图、文字区、留白、背景、光影。不能用一个“简约”回答代替各图决定，明确“设计全由你定”则直接落实决定而不继续强问。
4. 确认当前N张SCENE在single/four-grid/installation/comparison的分配，合计N；它们是呈现形式，不是产品分类。installation可指有据的使用、穿戴、维护等动作，无步骤需求就为0。四宫格仍是一张资产。步骤数量来自操作，而非四类就四步骤。对比可为本品两个已证状态/用途；不得凭空制造竞品失败或不当优越性。
5. 逐SCENE确认1:1像素1600/2000/2048，问题含ID与用途；用户“四张都2048”可整批记录。A+使用对应母版，不自动方图。
6. 每张先按[文案问答](copy-typography.md)问copyMode：none/minimal/informational/native-only。可一次明确列出所有ID让用户批量答，工具每批支持有限时拆开问。不因设计了11张就写11个口号。
7. 有字才给原始中/英文输入机会，或接收明确AI拟写决定；再按[字体分支](copy-typography.md#字体选择与最终文字区)选择字体并落实文字区。可按全套确认后逐图沿用；局部覆盖需记录。不要把这两个步骤压成一句“文案字体AI自定”。

只有明确“AI拟写/由你决定”才构成对应范围委托；空白、跳过、预选或弹窗没答都不是。用户委托设计后直接作出具体选择，不继续为每个道具要许可；事实缺口仍需处理。可并行推进不依赖答案的资料整理，但待答图不输出最终可执行稿。

## 采集后的参考选择弹窗

这是从研究进入设计的触发步骤，适用于new-set和set-refresh。采集成功、拥有图片文件、模型认为某套优秀，均不能代替用户的参考选择。已有明确回答或委托则复用，只问剩余未决项。

1. **先看图并展示候选。** 首批画面可用且足以说明方向时，就展示当前实际可见的1–3套候选；有多套可比较时优先2–3套。每套标明代号、真实ASIN/变体、gallery/A+图序、已看覆盖、适用目标ID、值得借鉴的关系与不适用之处，附可查看的图片预览或文件链接。不仅列ASIN/下载路径，也不把下载成功说成看过整套。只看过部分就标部分；不必等其他竞品、评论或三平台全部完成。
2. **第一批选提示词来源路线。** 未明确路线时，先检索并展示适配的[内置套图文字蓝图](reference-library.md)，再实际弹窗提供“刚抓取的竞品套图反推 / 内置套图提示词 / 具名混合”，允许自由输入明确原创。内置无配图标text-only，竞品只读到部分标覆盖；不伪造两者预览。用户只提供ASIN或说“分析竞品”仍需此问；明确“按这些竞品做”则沿用竞品路线，直接问未定主套；明确全面委托则代选并记录依据。只委托“配色你定”不能覆盖路线。
3. **选路线后问具体套图与程度。** 竞品路线确定真实主ASIN/变体/源图；内置路线确定ORD-SET及逐图模板；混合路线逐ID分配主辅。展示源图/文字蓝图→目标ID及保留/修改项，按[继承强度](reference-fidelity.md)确认reference-replace或structure-adapt等未决项，文字方案不声称完整继承未见源图。可按DIM/DETAIL、SCENE、A+分组确认，不机械逐张重问。用户已说“只替换本品、小改”直接记录reference-replace；“贴近A套，其余你定”可覆盖相应来源、程度与设计，不再让其重选原创。
4. **进入多轮逐图讨论。** 选了参考套图不等于所有细节已定。转回[多轮沟通循环](#多轮沟通循环)，按下一张/下一组brief展示具体方案并实际弹窗，每批1–2题；每次收到回答后继续下一未决项。无字图不问广告文案/字体；已答同批场景像素或全套字体就直接复用。未知尺寸/功能等产品事实另问，不以设计委托补造。
5. **落盘后再定稿。** 在discovery.md记录参考决定的status、route、sourceSets、transferMode、affectedAssetIds及原始回答/委托范围；layout-decisions.md逐ID记源图映射和细节状态。候选建议是proposed，已发送未答是pending，明确回答为confirmed，明确委托并已落实的选择为delegated。只有相关选择confirmed/delegated且事实足够，才允许该图进入最终可执行稿；其余制作/上传条件仍按交付状态判断。等待期间可继续采集、分析和拟草案，不能以“先交一版”绕过选择。

第一批异步弹窗调用示例（只在确有已展示的可用画面且路线未定时使用，推荐项按实际适配判断）：

```json
{
  "questions": [
    {
      "title": "已展示本轮竞品画面及内置文字套图方向。本次提示词主要沿哪条路线？之后继续确认具体套图、逐图来源与设计细节；内置方案当前是文字蓝图，没有配套原图。",
      "options": [
        "按刚抓取的竞品套图反推（推荐）",
        "选择内置套图提示词",
        "指定竞品与内置的混合来源"
      ]
    }
  ]
}
```

将此对象传给实际可用的`request_user_input_async`；示例或文字描述本身不算弹窗已执行。选参考后继续下一批来源/细节问题；不要发完第一问就把所有设计设为已确认。

在discovery.md记录referenceRoute=competitor-derived/library-template/hybrid/original、状态、用户原答/委托、主套/ORD-SET、库版本及逐ID来源。内置的推荐文案或结构仍是proposed，不自动确认场景分配、像素、文字模式或字体。

如果只有URL/下载文件但尚未看图，先完成视觉检查；无法查看时披露限制，完成有限恢复后可展示内置文字蓝图继续选择，不能声称已看过竞品或自动转原创。用户仅要求采集/研究、未要求策划本SKU图片时，不强行发生产设计问卷。

### 继承强度弹窗用大白话

具体源图选定后，未有明确程度回答/委托就实际问：“照着这张做，保留布景、道具关系、机位、排版与光影，主要换成本品与准确文案”，还是“保留排版，重新设计布景、机位与光影”。先展示同一源图两种做法的具体差别，不把代码模式名当唯一解释。只选“参考这几款”不等于选择了后者。按[参考继承强度](reference-fidelity.md)记录范围与逐图例外。

逐图方案要从已选源图展开：照着做时主要问真实SKU适配、冲突和用户想改的内容，不另提一组不相关布局诱导用户放弃源图；重新设计时才比较新的场景/骨架。缺使用事实的问题先说明拟展示的使用情境及最小缺口，再给补充/局部替代选项，不预设“全套空置”或把未知精密参数当所有生活场景必填。

## 文字与排版

三遍处理：保留原意、数量/范围/条件→自然英文→按画面空间精简。语法润色无需再次确认；改变意思、锁定话术或删掉承重条件要澄清。用英寸/厘米时依站点和已核尺寸，保持文案/尺寸线一致。

每条可见字符串指定位置框（0–100%坐标可用）、对齐、字号/字重、行距、行数、确切换行、颜色与对比度；必要的“not included”等不能缩到不可读。文字超区先改布局或经确认缩文，不能让图像模型自行删词。

自主方案优先直接利用自然留白，不默认每张左字右物+白色面板。确需面板/局部渐变写清边界、透明度/填色与产品缓冲区；渐变不覆盖完整轮廓和操作点。竞品来源按[参考改造](reference-redesign.md)借鉴可读的层级关系，保留其成熟层级和字系，按背景融合规则具体调整文案及字色，不自动重做整套视觉表达。字体保持协调，以字重/大小建层级。尺寸/事实可读性优先于装饰字。

none指无新增文案，不抹除商品自带可见印字；native-only表示文案在A+原生字段，图片保持无烘焙文字。不要把内部P/V/S-ID或研究备注生成到图上。

## 弹窗执行机制

需要回答时必须实际调用可用的提问工具，不能只在正文写“请确认”或交付一张待填表。优先 `request_user_input_async`；只有当前模式明确支持时才用 `request_user_input`，不可为问问题自行切换模式。两者不可用才在聊天询问并说明。文字弹窗只收文字，补图在聊天请求。

在以下决策发生时检查已有答案，未解决就弹窗，通常每批1–2题，提供有事实依据的2–3个选项并允许自由输入：
1. 图间是否同SKU/不同状态、结构/尺寸/功能冲突，以及配套物是否可放入、真实容量/净空。
2. 首批可用竞品看图后尚未决定提示词路线、具体套图/图位和继承强度，执行上节，不以采集成功或默认模板跳过。用户已说“按竞品少量改”时直接记为reference-replace，只问尚未确定的来源及细节。
3. 场景分配、逐图方图尺寸、有字/无字、文案来源及字体等尚未被明确回答或委托的决定。可批量回答并逐ID记录，不要求用户重复已提供资料。

问题写明图号/差异、所需答案与影响。示例：“SCENE02拟展示狗躺在笼内，目前只有外尺寸。请确认内部净空和适用体型，或选择本图先展示空笼。”不把猜测数据设置为推荐项。

记录questionId、affectedAssetIds、question、answer、status及delegationScope，并以实际工具调用和用户回复为依据，不补写不存在的弹窗/回答。异步提问后继续不依赖答案的研究，后续问题按当前答案推进，避免对同一范围同时发出相互依赖的多组弹窗。不把等待时长、关闭弹窗或默认预选当回答。必要事实未答仅阻塞依赖图；可选设计经合理等待可给明确标注的提案，不能冒充confirmed或READY。用户全面委托可免设计选择弹窗，但不能替代产品事实；有任何具体身份/适配疑问仍问。
