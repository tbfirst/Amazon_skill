# 文案与字体的多轮问答

在确定最终图上文字、A+原生文案或相关prompt前读取。沿用[多轮沟通循环](discovery-layout.md#多轮沟通循环)：先展示本批ID、任务与文字位置，再实际弹窗，回答后继续下一未决项。维护本技能时直接改规则，不要求用户提供未来商品的文案。

## 先逐图确定是否要字

每张资产分别落实`copyMode: none | minimal | informational | native-only`。每批通常1–2题，每题包含一个ID、用途及推荐；用户也可一次逐ID回答或明确给整组规则。整体风格、参考套图选择、允许AI写文案均不自动确定各图是否要字。已有逐图回答或明确覆盖该项的委托直接沿用。

可用异步工具调用示例（按实际任务改写问题与推荐；若DIM已调整为规格/适配任务，相应替换“尺寸”）：

```json
{
  "questions": [
    {
      "title": "DIM01用于买前尺寸判断，图上文字怎样安排？选择完全无字时，需要再明确本图如何传达尺寸。",
      "options": [
        "只保留必要尺寸标注（推荐）",
        "增加短标题和尺寸标注",
        "完全无字，另讨论信息表达"
      ]
    },
    {
      "title": "DETAIL01用于看清已选细节，图上是否需要新增文案？",
      "options": [
        "仅加必要部位标签（推荐）",
        "增加一个简短标题",
        "无新增文案"
      ]
    }
  ]
}
```

将对象传给实际可用的`request_user_input_async`才算执行，不以示例文本代替。待这一批回答后，再问有字图的文案来源，不能在同一批默认用户选了有字。推荐项依据当前任务，不要求所有项目使用示例选项。

- `none`：无新增文字；保留商品原本可见的真实印字。文案来源和字体记not-applicable，不继续问标题。
- `minimal`：少量标题/短语；必要的销售边界或条件不能因“少字”而消失。
- `informational`：尺寸、规格、部位、步骤或其他必要标签；数字/单位同样属于文字。若用户说“不要文案”，澄清是去营销标题还是连参数都删，不能静默保留或删除。
- `native-only`：图片不烘焙文案，文字交给A+原生字段；继续落实文案来源和准确内容，自定义图片字体选择不适用。

## 有字后收基础文案或AI拟写决定

为有字/原生文字的资产提供整套或本批输入机会，不要求用户重复填11遍。自由输入题可写：

> 请填写本批DIM01、DETAIL01想表达的中文或英文基础文案，可按“ID：标题 / 标签”输入，标明必须原样保留的词句；也可明确回复“这两张由AI拟写”。AI会按已核事实保留原意并润色英文。

用户还未决定输入方式时，可先给“我填写基础文案 / 这些ID由AI拟写”两个入口，再按回答展开。实际要收原文时使用无options的文字输入题；上传文稿图片的请求放在聊天，不让文字工具接附件。

分别记录`copySource: user-polish | ai-generate | not-applicable`，与copyMode分开：

- 有输入：保存原文与锁定词，执行保义、自然英文、版面适配三遍编辑。普通语法润色无需另问；改变卖点、数值、条件或锁定词时，给出具体差异并问该项。
- 明确“AI拟写/文案你写”：仅在所指ID范围内按已核事实拟写。没有提交的ID仍待答，除非用户明确“其余也由AI写”。
- 未回复、关闭、超时、默认预选不代表AI授权。只有工具能区分“已提交空白”且题目事先解释该空白表示委托时，才据实际提交记录；工具不提供这种状态时，要求明确回复“AI拟写”，不要推测空白含义。
- “无字”是copyMode=none，不是AI生成。用户已确认的旧文案/共用短语直接复用，不重新索要；旧图里看得见但未确认保留的句子只是待核输入。

收到输入或拟写委托后，展示简短“原文或主题 → 拟用英文 → 修改原因”。不强制逐句再批准普通润色；有新主张、含义歧义或锁定词冲突才续问。用户原文中的性能、成分、适配、随货数量也要核P证据，不能因用户提交或竞品出现就视为已证。

## 字体选择与最终文字区

只对需要烘焙文字的图问字体。先读已选参考及用户规范：明确选择保留源图字体搭配或已有全套字体回答时直接沿用；仅说“参考A套”而字体处理未定时，仍给具体保留/替换方案。不要用统一字体菜单覆盖已经选定的源图层级。

未定字体时，第一批提供“AI匹配 / Apple风格现代无衬线 / 查看其他字体方向”，用户选第三项后再展开“基础无衬线 / 经典衬线 / 克制展示或手写”，允许输入品牌规范。Apple风格描述简洁的字形气质，不保证加载特定字库。用户明确委托AI就定出具体字形/层级，不为每个字号重复求许可；仅预选AI仍为pending。

同一字体可一次覆盖明确列出的全套/本批ID，局部例外单记；无字图不因此加标题，native-only使用平台原生字体。字体已定后，只对尚未选择且会改变画面的文字区给具体候选，如“直接利用顶部场景留白”或“右侧窄列标签”，不只问“高级还是简约”。已选背景融合规则和商品保护区持续适用，不自动新增底板。

最终brief/prompt只写一个确定方向：精确英文字符串、换行、文字框、字形/字重、字号层级、对齐、行距和颜色。先保留条件，再自然润色，再缩短到可读篇幅；不用通用广告口号替代每张图的具体任务。无字图不输出空标题占位。

### 按任务编辑，再形成文字地图

与植株版相同，三遍处理是保义与条件→自然英文→画面篇幅。标题指出本图唯一主题，辅助句增加有据解释，标签回答部位/参数/销售边界；不把11张写成同义口号。整套统一商品词、单位、大小写、标点和数量口径，数字及锁定词不因润色擅自换算。

|任务|文字优先级|起稿建议（不是平台限制）|
|---|---|---|
|尺寸/规格/适配|准确对象、状态、数字/单位优先|标题可省，必要标签就近绑定对应线或视图|
|可见细节|一个主题与不同部位标签|标题约3–6词，短标签直接说明部位，不把外观写成性能|
|单场景|让场景表达任务|标题可无或约3–7词，辅助句只加新信息|
|多格用途/步骤|每格一个任务或动作|并列短语/平行动词，条件与顺序不能为简短而删除|
|比较/选择|对比轴、变量及必要限制|两侧层级和句式对等，不加未经支持的分数/优越性|
|A+|递进叙事与可读解释|按横幅重排，较长说明可用已选原生字段，不能烧进无字图|

按[八种文字布局](text-layouts.md)在已选图像骨架上比较适配的少量文字区，再逐元素形成exact_text/line_texts/zone/type/text_surface/emphasis/protection。各行拼接还原最终文字，数字与单位、否定与条件不拆开。拥挤时先去重复、调断行/文字区、在授权内调取景，再考虑已选原生字段，最后微调字号；不能靠盖住商品或缩小必要限定解决。只在含义/锁定词或已选骨架发生冲突时继续问，不为每次正常语法修饰重复求批。

`none`仅指无新增文案。若已选参考或设计委托包含从属主题线描/剪影等，按[图形点缀](scene-props.md#分开四种角色再决定画什么)单独落实，不因无字自动删除，也不因允许图形自动加字。图形不得成为未经证实的认证、功效或精确适配示意。

## 记录与继续

layout-decisions.md逐ID分别保存copyMode、copySource、用户原文/锁定词、最终英文、fontChoice、文字布局及各项状态/回答依据；discovery.md保存共用规则、覆盖ID和nextQuestion。收到一项回答只更新该项，再问下一个会改变结果的未决问题。文案未答不自动变无字，字体未答不自动变AI，文字模式已答也不代表文字内容已授权。

明确“这组文案、字体和排版都由你定”时，展开为具体内容并记delegated，不机械重复询问。设计已落实后才定稿相关prompt，待答项保留在brief/阻塞草案；文字设计检查不表示已验证生成字形或小屏渲染。
