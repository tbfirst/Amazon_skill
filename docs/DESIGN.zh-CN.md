## 已确认设计

| 项目 | 决策 |
| --- | --- |
| 入口 | 用户大白话与商品图，可带多图参考或连续修改 |
| 执行 | 理解需求、整理提示词并直接生图；关键缺失才询问 |
| 优先级 | 商品一致性 → 物理融合 → 构图控制 |
| 商品 | 真实/仿真植物、花环、花束、盆栽、花箱 |
| 资产 | 实拍指导、缺失角度检查、透明主体、花叶杆特写、空容器和背景 |
| 保护 | 按售卖内容保护；随货盆与道具盆区分 |
| 造型 | 默认保留，明确要求时允许实物可实现的弯折、展开与排列，数量和部件身份不变 |
| 混搭 | 其他装饰花材仅在明确要求时添加 |
| 默认环境 | 自主选择合理欧式生活空间和载体，符合欧美实际使用 |
| 尺度 | 场景允许视觉匹配，尺寸标注必须真实 |
| 文案 | 默认模型直接绘字；细节外观文案可自行写简短英文；性能和规格需要确认事实 |
| 交付规格 | 用户指定；可沿用任务内已确认规格；不设固定默认像素/格式/张数 |
| 模型 | 沿用 Lovart 用户选择；不把用户当前常用型号写成技能依赖或可用性保证 |
| 修复 | 首次生成不计入，随后全任务最多三轮；跨模块、候选与回退共享 |
| 参考与历史 | Agent 自选本轮参考，真实资料为事实源；历史留档使用 Lovart |
| 图种 | Amazon 美国站白底主图、场景附图、特写、单张尺寸/细节/卖点/A+ |
| 语言 | 英文执行规则；沿用用户交流语言，未明确时中文；美国站画面文字默认英文 |
| 发布 | 第一版本纳入本地 Git 初始提交；由用户配置远程并推送；许可证暂缓 |

英文用于术语和国际协作的一致性，不宣称单凭英语就能提高出图质量。

## 集合与功能模块的边界

一个可发现的 skill 放在一个同名目录中，name/description 说明何时使用。宿主完成安装和发现后才具备自动选用的条件；技能本身不保证所有 Agent 都自动扫描所有仓库。

第一版的八个模块继续共用商品保护规则，避免融合、构图与精修各自改写售卖事实。references/lovart.md 专门描述原生平台与外部 Agent 的执行条件，不虚构接口，不绑定原应用源代码。

LOVART_INSTRUCTIONS.md 从入口和直接引用模块生成，是原生 Lovart 的完整文本交付；安装型 Agent 按需读模块，Lovart 读取完整文本后按任务选规则。两份内容通过构建检查保持同步。

agents/openai.yaml 是可选宿主元数据，允许隐式调用；无图标、密钥、假连接依赖或额外配置要求。目录符合通用 Agent Skills 形式，但实际自动发现仍取决于宿主。

无根级总 SKILL.md，也无未实现的占位 skill，避免安装器把整个集合识别为一项泛化技能或发现尚不能工作的功能。

## 运行与用户体验

若用户仅给商品图并说“放到阳台”，能确认商品范围和交付设置时直接选择现实欧式阳台及合适道具；只有换盆涉及未知售卖范围、尺寸图缺实测值、目标对象不清或必要输出规格未知时追问。

外部 Agent 未连接 Lovart 时完成提示词和图源角色整理，如实说明未生图。接入 Lovart API 与控制网页会话是不同执行路线，不能假设 API 沿用网页模型设置。安装工作规则不替用户开通工具、账户或接口。

不强制每次附上所有历史图片，也不把已生成的错误枝叶作为新事实。自动修复三轮后仍失败时，指出具体问题及需要的素材或决定。一个候选通过后不随其他失败项重复重绘。

## 原路线图与当前进展：整套 Amazon 图片

原计划中的 amazon-image-suite 现以 amazon-plant-image-strategy 名称落地为独立策略技能。当前包含商品事实、多轮引导、竞品评论与关键词研究、图片顺序、完整单图 Brief 及 Lovart 提示词；自动执行整套生图仍不在本轮范围。

2026-10-16 最新确认：输入产品原始素材与3–6个不同竞品ASIN，并行浏览研究；图数改为尺寸图1张、细节图1张、场景图4张、A+图5张，共11张，不含新增主图。默认美国站、中文策略与英文提示词；每张明确布局、光线与阴影，五张A+按真实模块适配。批量生产与实图验收需另行按实际用户任务进行。

product-image-review 仅在出现独立审图需求后考虑拆出；当前质检保留为共用模块。不要让新技能再维护一套互相冲突的商品保护规则。
