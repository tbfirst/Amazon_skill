## 工作流程

读取产品原始资料 → 售卖事实与身份锁 → 竞品研究及有序整套图谱 → 检索库候选与目视选定参考 → 展示具体方案 → 弹框选择尺寸/细节、四场景与五A+序列 → 记录11张版式骨架与统一规范 → Brief → 独立Lovart提示词 → 从单张TXT编译Markdown/TXT总汇 → 一致性检查。

不设死板轮数，用户已提供的信息不再询问。用户要求直接出稿时可跳过访谈，但未知事实仍不能进入可执行提示词。`discovery.md` 支持续聊，避免每次重新问起。

竞品执行步骤已细化为：

1. 标准化输入并按站点+ASIN去重，核对落地商品、颜色、尺寸及套装变体。
2. 默认同时处理2个独立标签页，稳定后可提高到3个；先完成所有竞品的身份检查与图库/A+盘点，避免在第一个商品上耗尽时间。
3. 展开更多图片，逐张切换大图并确认实际画面；分别记录盘点总数和已目视数量。A+ 识别原生模块与独立图片，检查懒加载区域。
4. 对可访问评论做分层抽样，默认每竞品最多30条原文、最多5组相关买家图片；记录抽样偏差、n/N和重复父子变体。AI摘要与评分概览不计入原文样本。
5. 按错误信号恢复：导航超时先检查页面是否已落地，再尝试可用的页面状态/DOM/截图；直链不通再走正常浏览器公开搜索入口。登录或验证码限制如实标记，其他区段继续。
6. 每完成一个区段保存 ASIN 检查点，续跑只补缺项；主代理汇总跨竞品矩阵，将实际视觉证据映射至11张图的独立布局和光影建议。
7. 离线脚本检查记录一致性，人工再核对来源与结论、竞品观察与我方事实之间的边界。

详细操作与停止条件见 [浏览器研究步骤](../skills/amazon-plant-image-strategy/references/browser-research.md)，字段与命令见 [研究检查点](../skills/amazon-plant-image-strategy/references/research-records.md)。

## 设计中的关键区别

- 评论主题解释买家为什么犹豫，不证明我方具备相应性能。每条卖点需要适用的产品依据。
- 反 ASIN 估计、SQP 口径、公开搜索观察和语义推测分别记录；没有工具时不编造自然流量词及其指标。
- 保留自然外观与真实售卖状态。仿真不加叶增密，活体不以成熟盛花状态冒充幼苗；随货盆与道具盆分开。
- 固定编号为 DIM01、DETAIL01、SCENE01–SCENE04、APLUS01–APLUS05；截图旧示例里的 A+6/12张不覆盖用户当前确认的11张。
- A+ 三图模块占用五张预算中的三张；原生文字字段另交付，不拼成无法上传的大图，不静默扩数。
- 每张分别描述布局分区、主体占比、文字层级、景别/视角、光源方向和软硬、画面明暗/反差、接触阴影与投影、背景和道具。标明竞品实际观察与我方独立设计建议。
- 场景有2–3个可识别建筑锚点与前中后景；画幅占比与实物对门窗/家具比例分别控制。四场景不以换墙色代替任务差异。
- A+形成定位、用途/选择、细节、使用、规格等适配叙事；可用横幅、场景组合、网格、步骤栏和参数分区，不将五张全做同一左右布局。
- 按商品选择主/次/点缀色，指定字体层级、字重、行数与留白；参考的奶油绿棕色不成为全品类模板。文字不覆盖关键花叶和测量端点。
- 光影按任务选择日照、窗光、逆光补光、低角度长影、真实窗格影或冷暖暮色；明确光源大小/高度、亮暗面、补光及承影面，不统一使用柔光淡影。挂件不画盆底地影，新环境不残留源图旧影。
- 缺必要商品身份/实物尺寸的受影响prompt放在blocked；默认制作画布已知，不因A+账号未知阻塞全套方案，上传复核与成图验收分别标注。
- 用户明确授权测试且规格自行决定时，可给具体测试画布/暂拟模块并标PROVISIONAL；正式账户上传待核对，商品事实仍不得补造。
- 每条 prompt 重复完整身份约束、视觉规则、参考图角色与准确英文文案，可以单独复制使用。
